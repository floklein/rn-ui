---
title: Native Host
description: What core asks of React Native, and how a native adapter answers.
---

On React Native, a part is a view, not an HTML element. Core never imports `react-native`. When it needs something only the app's views can do, such as moving a screen reader's focus to a part, it asks the **native host**, which `@ui-sdk/react-native` implements.

You don't call anything here to use the components. This page is for building an adapter, or for reading what a native component does under the hood.

## The Host Interface

`@ui-sdk/core/native` exports the `NativeHost` type, `setNativeHost`, which registers the host, and `nativeHost`, which returns the one registered now, so a check can wrap it to see what core asks. `@ui-sdk/react-native` calls it once, as it loads:

```ts
import { setNativeHost } from "@ui-sdk/core/native"
import { AccessibilityInfo, I18nManager } from "react-native"

setNativeHost({
  focus(part) {
    const view = viewOf(part)
    if (view) {
      if (isTextInput(view)) {
        view.focus()
      }
      AccessibilityInfo.sendAccessibilityEvent(view, "focus")
    }
  },
  field: (part) => fieldInside(part),
  announce(text, priority) {
    AccessibilityInfo.announceForAccessibilityWithOptions(text, {
      queue: priority === "polite",
    })
  },
  activate: (part) => controlOf(part)?.(),
  compare(a, b) {
    return viewOf(a).compareDocumentPosition(viewOf(b)) & 4 ? -1 : 1
  },
  isRTL: () => I18nManager.isRTL,
  box: (part) => viewOf(part)?.getBoundingClientRect(),
  follow: (part, drag) => followTouches(part, drag),
  adjustable: (part, step) => routeAdjustments(part, step),
  scrollNear: (point, options) => scrollAreasUnder(point, options),
  listen(next) {
    input = next
    return () => (input = undefined)
  },
  seen: (part) => renderedOf(part),
})
```

- `focus(part)` requests accessibility focus on the part's mounted view, and starts editing when the view is a `TextInput`. The accessibility focus request is never treated as done: with no screen reader running, it moves nothing. A part with no view asks nothing, so a controller's `focus()` after its component unmounts does nothing.
- `field(part)` returns the text field rendered inside the part's view, a `NativeTextField`, or `undefined`. An InputGroup's presses reach its field through it, where the web finds the field in the group's element: a press on the group's text starts editing the field, and its Clear part empties the field and starts editing it.
- `announce(text, priority)` has the screen reader say `text`. On iOS, `"polite"` waits for what VoiceOver is saying and `"assertive"` interrupts it; Android has no such option. Core's `announce`, and a Button's `pendingAnnouncement`, go through it, where the web writes into a live region.
- `activate(part)` activates the control that joined the Field of `part`, as a press on its label does: it starts editing a text field and presses any other control, like a switch. A FieldLabel's press goes through it, where the web finds the control in the field's element.
- `compare(a, b)` says where two mounted parts render: negative when `a` comes first. A group orders its members with it, like a toggle group's value, which lists the pressed toggles in the order they render. `@ui-sdk/react-native` compares the parts' views in React Native's view tree.
- `isRTL()` says whether the app lays out right to left. Core's `isRTL(el)` reads it for the whole app and ignores the element, since React Native has one direction for every screen.
- `box(part)` measures the part's mounted view on screen, in the coordinates touches report, or returns `undefined`. A slider reads its track's box when a drag starts, as the web reads the track's `getBoundingClientRect()` once per press.
- `follow(part, drag)` follows the touches that start on the part's view with a `NativeDrag`, until the cleanup it returns runs. With `capture`, the view takes its children's touches too (`pointerEvents="box-only"`). `@ui-sdk/react-native` makes the view a responder: `accepts` decides whether a touch takes it, from where it starts, and `start`, `move` and `end` get each `NativeTouch`, its position and the innermost part under it. A responder cancelled, or taken by another view such as a scroll view, calls `cancel`. The view refuses to hand the responder to a scroll view around it, as `touch-action: none` does on the web; on iOS a scroll view along the same axis still scrolls during the drag unless the app turns its `scrollEnabled` off, as [Slider](/docs/react-native/components/slider#inside-a-scroll-view) shows. A [Scroll Area](/docs/react-native/components/scroll-area#drags-inside)'s viewport turns its own off while a drag inside it holds the touch.
- `adjustable(part, step)` routes a screen reader's increment and decrement on the part's view to `step`, with `1` or `-1`, until the cleanup it returns runs, where the web hears a range input's `input` event.
- `scrollNear(point, { edge, speed })` scrolls each [Scroll Area](/docs/react-native/components/scroll-area#drags-inside) under a dragging finger a step toward an edge it's within `edge` points of, the innermost first along each axis, and returns whether any scrolled. Core's `createAutoScroll` calls it once per frame while a reordering drag holds still near an edge, where the web scrolls any scrollable element and the window. A plain `ScrollView` never scrolls this way.
- `listen(input)` hears what dismisses a popup while one is open, and returns what stops it. The host calls `input.back()` for Android's back, from a `Modal`'s `onRequestClose`, `input.escape(api)` for VoiceOver's escape gesture on a popup's content, and `input.outsidePress()` for a press on a modal popup's backdrop. Each goes to the topmost open popup, and returns whether one took it: a popup that refuses the dismissal still takes it, so back never falls through to navigation.
- `seen(part)` returns what an agent reads of the part's view, a `NativeSeen`, or `undefined` while the part renders none: its accessibility label and role, the plain text inside it, whether it's disabled or hidden from accessibility, the `data-agent-*` marks around it, the instances it renders inside and its press. The agent bridge from `@ui-sdk/core/agent` reads every part through it, where the web reads elements, as [Connect an Agent](/docs/react-native/agents) shows.

A press the host delivers names its source with `nativePressSource`, from `"touch"` or `"virtual"`, which reports `"agent"` instead while the agent bridge presses, so the changes the press causes say the agent made them.

Core's locale on native comes from `Intl`: the page's and the user's language are the device's, and a component's `locale` option still wins.

## Native Behavior

On the web, a slot's `bind` runs while its element is in the page, and does what needs the element: a toggle joins its group there. The native host never runs `bind`. A `NativeBehavior` from `@ui-sdk/core/native` restates it: one function per slot, which runs while a part of that slot is mounted and returns its cleanup.

```ts
import { toggleNative } from "@ui-sdk/core/native"
import { toggle } from "@ui-sdk/core/toggle"
import { createParts } from "@ui-sdk/react-native/primitive"
import { Pressable, View } from "react-native"

const parts = createParts(toggle, { root: Pressable, icon: View }, toggleNative)
```

`createParts` and `usePrimitive` take it as their last argument. `toggleNative` is Toggle's: while a toggle's root is mounted it joins its group, so the group knows its toggles in render order, refuses a disabled one and can focus one. `checkboxNative` does the same for a checkbox in a checkbox group, and `radioNative`, `ratingNative` and `segmentedControlNative` for each radio in a radio group, a rating or a segmented control, so the group focuses its checked radio. `tabsNative` is Tabs': while a tab is mounted it joins the tabs' roving group, so the tabs know their tabs in render order, select the first enabled one when nothing is selected and can focus the selected one. `toolbarNative` is Toolbar's: while a button, link or field is mounted it joins the toolbar, so the toolbar knows its items in render order and its controller can focus the first enabled one; toggles join it through `toggleNative`. `collapsibleNative` is Collapsible's: while its panel is mounted it reports when the panel settles, so `onOpenChangeComplete` runs once an opening appears and once a closing's `onExit` calls `done`. `accordionNative` is Accordion's: while an item is mounted it joins the accordion, so items know their index in render order, and each panel settles as Collapsible's does. `fieldNative` registers a Field's label, description and error parts while they're mounted, so the control's label and hint come from the parts that render. `gaugeNative` is Progress's and Meter's: while the root is mounted it reads the locale the value is formatted in, and while a label is mounted it names the root. `dialogNative` is Dialog's and Alert Dialog's: while the content is mounted and the dialog open, it is a layer that back, the escape gesture and a backdrop press close, it asks the host to focus the title on open, or an alert dialog's first Close part, and the trigger on close, and it keeps the dialog mounted until the content's `onExit` calls `done`. `popoverNative` is Popover's: the same layer, with focus on its title, or on the content after a touch. `tooltipNative` is Tooltip's: the same layer, which never takes focus, with the content joining the tooltips' warm group while it's mounted, and VoiceOver's escape gesture on its text going back to the trigger. `sliderNative` is Slider's: its root reads the locale, its control follows touch drags along the track with the calls the web's pointer handlers make, and each thumb takes a screen reader's increment and decrement. A drag that is cancelled, taken by a scroll view or unmounted puts the value back and commits nothing. `colorPickerNative` is Color Picker's: its root reads the direction, its area and each slider follow touch drags with the calls the web's pointer handlers make, and each thumb takes a screen reader's increment and decrement as one step. A drag cut short the same way puts the color back. The host draws the parts through `nativeColorPicker(api)`, which turns what the web writes as CSS variables into colors and gradients React Native draws: `color`, `areaBackground`, `areaRows` for an area no two gradients draw, `areaThumb` and `sliderBackground`. `numberInputNative` is Number Input's: its root reads the locale, and a scrub area follows touch drags, stepping by distance, committing on lift and starting to edit the field after a tap. `resizableNative` is Resizable's: while its panels and handles are mounted they join the group, which orders them by where the host renders them and measures the panels with `box`, each handle follows touch drags with the calls the web's pointer handlers make, putting the layout back when a scroll view takes the touch, and takes a screen reader's increment and decrement. The group reads no layout itself: the host calls `nativeResizable(api).measure()` once the group has laid out again, so panels sized in points keep their size. `drawerNative` is Drawer's: Dialog's, with the sheet attached to the content while it's mounted, and the handle stepping through the snap points on a screen reader's increment and decrement. The sheet meets the host through `nativeSheet(api)`: the host sets its `view`, which measures the screen and the content, moves the content and plays the shared spring, and feeds its `input` one finger's touches with the scroll view under it. `calendarNative` is Calendar's: its root reads the locale and today, and while a day is mounted it joins the calendar's roving group, so the controller's `focus()` and a press on a day of another month can move the screen reader to a day. `datePickerNative` is Date Picker's: Popover's layer with focus on the calendar's day with the tab stop, Calendar's root and days, and its hint, which describes the inputs while it's mounted. `datePickerText(state, end)` gives the text its input shows, what was typed or the date in the locale's format. Scroll Area has no behavior object: its engine meets the host through `nativeScrollView(api)`, which the host hands the mounted `ScrollView` to scroll (`attach`), reports its scroll events and layouts to (`report`), counts its scrollbars and their lengths with, and feeds a scrollbar's touches (`press`, `move`, `lift`); the thumbs read their length and offset from `thumb(axis)` whenever `watch` calls them. `toastNative` is Toast's: while a toast is mounted it follows the touches the host's `follow` hands it, also one a button inside took once it moves (`NativeDrag`'s `claims`), and turns them into the web's swipe, which pauses the timers and dismisses the toast or lets it go back. The host reads where each toast is through `nativeToast(api)`, whose `swipe(id)` gives the offset and, once a swipe dismissed it, the direction.

A component you build on [reordering](/docs/core/behaviors/drag-and-drop) binds its parts with functions instead, since their slots are yours. `bindReorderItem(reorder, part)` joins an item to a `createReorder` list and follows the touch drags that start on it. `bindTransferList(transfer, part)` joins a list to a `createTransfer` and follows the touch drags that start on its items, and `bindTransferItem(transfer, part)` joins an item. The list's view takes its items' touches and finds the item under the finger by its box: an item that moves to another list renders as a new view there, and a touch on its old view would end with no release. So an item's own buttons take no touches; put them outside the list.

```tsx
const parts = createParts(
  packing,
  { root: View, list: View, item: View },
  {
    list: (part) => bindTransferList(part.api.transfer, part),
    item: (part) => bindTransferItem(part.api.transfer, part),
  }
)
```

A touch picks the item up once it moves past the drag threshold, so a tap stays a tap. As on the web, where the items set `touch-action: none`, a swipe that starts on an item drags it instead of scrolling, so leave the list room to scroll beside its items. Render an item as a `View` with no press: a `Pressable` takes the touch first, and development warns. The list renders the draft as the item moves, the item's state can say it's being dragged, and lifting the finger commits it in one change with the `"drag"` reason. A responder cancelled, taken by a scroll view or unmounted puts the item back and commits nothing. The moving item doesn't follow the finger between places, since the web's `--drag-x` and `--drag-y` have no native counterpart, and an item the app doesn't `label` is announced by its key, since core can't read a native view's text. The `preview` option and the keys work on the web only. A screen reader user reorders through actions the app adds, with `reorder.move(key, index)` or `transfer.move(key, list, index)`. Near an edge of a Scroll Area the drag scrolls it; inside a plain `ScrollView` along the same axis, turn its scrolling off for the length of the drag, as [Slider](/docs/react-native/components/slider#inside-a-scroll-view) shows, from the item's responder events.

A popup's trigger is pressed with `pressTrigger(part, source)`, where the web reads how it opened from the event: `"touch"` for a finger, `"virtual"` for a screen reader. Where focus goes on open follows from it, as on the web. A popup placed beside its anchor gets its position from `placeNative(api, measured)`: given the anchor, the popup and its arrow measured in the host's coordinates and the space it may use, it returns where the popup goes and the state fields the web writes as CSS variables and data attributes, like `side`, `availableHeight` and `arrowOffset`.

## Focus From a Controller

A controller's `focus()`, like Switch's or Input's, goes through the host. On the web it focuses the part's element. On React Native it asks the host to focus the part's view, which starts editing a text field. A toggle group's `focus(value)` does the same for one of its toggles.

## Presence

On the web, a part that animates out, like a checkbox's indicator, stays in the page until its CSS animations finish. React Native has no animation core can read, so the app says when an exit ends. A part whose slot takes `keepMounted` takes `onExit` on native, typed by `ExitProps` from `@ui-sdk/react-native/primitive`. When the part starts leaving, it calls `onExit` with `done`, and stays mounted until `done` runs or two seconds pass. Meanwhile it stays on screen, even where its slot would hide it, like a tab panel whose tab was just deselected, takes no touches and is hidden from screen readers. Its state gains `startingStyle` and `endingStyle`, the web's `data-starting-style` and `data-ending-style`. A part you build with `createParts` or `usePart` gets all of this from its slot. A native behavior hears when the part settles through `onSettled(part, listener)` from `@ui-sdk/core/renderer`: with `true` once it entered, and `false` once its exit ended, even after its view is gone.

## Checking a Native Component

`@ui-sdk/react-native/testing` checks a native component with no device, the way `@ui-sdk/core/testing` checks a web one. Each check takes the host tree your test renderer rendered and the OS, and imports no renderer: pass your renderer's `act` so each action renders.

```tsx
import { act, render, screen } from "@testing-library/react-native"
import { checkPattern } from "@ui-sdk/react-native/testing"
import { Platform } from "react-native"

await render(
  <Switch aria-label="Wi-Fi">
    <SwitchThumb />
  </Switch>
)
await checkPattern(screen.container, "switch", { os: Platform.OS, act })
```

- `checkPattern` takes the `"button"`, `"checkbox"`, `"disclosure"`, `"img"`, `"meter"`, `"progressbar"`, `"radio-group"`, `"separator"`, `"slider"`, `"switch"`, `"tabs"` and `"textbox"` patterns; `"button"` is native only, since the web check has no button pattern, and covers toggle buttons too: each needs a pressed state that activation flips. It checks roles, required states, names, one accessible element per item and hidden content, then performs the accessibility actions a screen reader user has and reads the state after each: activate everywhere, increment and decrement on a slider, escape on iOS, expand and collapse on Android. Opening and closing must request accessibility focus.
- `checkDirection` renders the component left to right and right to left, performs each action, and checks both directions end the same.
- `checkCreation` checks that creating a primitive and rendering its parts reads no web global and asks the native host nothing.
