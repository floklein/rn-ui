Use a segmented control to switch between a few views or settings, like List and Grid. It works like a radio group with one value, each item is its own accessible element, and its indicator follows the checked item.

/>

## Installation

```bash
npm install @ui-sdk/react-native @ui-sdk/core
```

## Composition

Use the following composition to build a `SegmentedControl`:

```text
SegmentedControl
├── SegmentedControlIndicator
├── SegmentedControlItem
└── SegmentedControlItem
```

`SegmentedControlItem` renders a `Pressable` with the radio role and its checked state. `SegmentedControl` and `SegmentedControlIndicator` render a `View`. Give each item a `value`. The control's value is the checked item's value, and the indicator sits behind that item.

## Usage

Import the parts and put them together. Put each item's text inside it: the text names the item.

```tsx
import {
  SegmentedControl,
  SegmentedControlIndicator,
  SegmentedControlItem,
} from "@ui-sdk/react-native/segmented-control"
import { Text } from "react-native"

function Example() {
  return (
    <SegmentedControl aria-label="View" defaultValue="list">
      <SegmentedControlIndicator />
      <SegmentedControlItem value="list">
        <Text>List</Text>
      </SegmentedControlItem>
      <SegmentedControlItem value="grid">
        <Text>Grid</Text>
      </SegmentedControlItem>
    </SegmentedControl>
  )
}

export { Example }
```

Name the control with `aria-label`, and show the same words as a heading above it. A container's name may reach no screen reader yet, since React Native has no way to give one a name, so make each item's own name clear without it. Without `defaultValue`, nothing starts checked.

## Indicator

`SegmentedControlIndicator` marks the checked item. Render it inside the control: its state holds the checked item's box in the control, measured from the layouts of the control and the items placed straight in it. Position the indicator absolutely with those fields to draw the background that follows the choice. It measures again when an item or the control is laid out again.

```tsx
<SegmentedControlIndicator
  style={(state) => ({
    position: "absolute",
    left: state.indicatorLeft,
    top: state.indicatorTop,
    width: state.indicatorWidth,
    height: state.indicatorHeight,
  })}
/>
```

The fields are unset until the control and the checked item have been laid out, and while nothing is checked. `indicatorLeft` and `indicatorRight` are what the `left` and `right` styles take: when the app runs right to left, React Native reads those styles from the other side, and the fields swap with them. Render the indicator before the items to draw it behind them.

## Disabled

Set `disabled` on the control or on one item. A disabled item ignores presses, leaves Tab's order on Android, and screen readers announce it as dimmed or disabled.

## Read-Only

Set `readOnly` to keep the value while people still reach and read the items. It isn't announced, so say why in the labels or nearby text.

## Controlled

Pass `value` and update it in `onValueChange`. Call `details.cancel()` in the callback to keep the current value. A [controller](#controller) from `createSegmentedControlController()` checks an item from anywhere, like the Show Month button below. Create one controller per mounted control.

## Forms

A native view takes part in no form, so the control has no `name` or `form` prop and renders no hidden input. Read the value from `onValueChange` or a controller, and reset it by setting it. `required` stays in the state for your styles and labels.

## Styling

Style each part with a function of its state, like `(state) => [styles.item, state.checked && styles.checked]`. Each part receives the fields listed under [Part State](#part-state). An item gets a second argument, `{ pressed, hovered, focused }`, for press feedback, and keyboard focus on Android.

## Accessibility

A segmented control is a radio group, so it follows the [WAI-ARIA radio group pattern](https://www.w3.org/WAI/ARIA/apg/patterns/radio/), translated to React Native's accessibility props. Each item has the `radio` role with its checked and disabled state, so VoiceOver and TalkBack announce it as a radio button, checked or unchecked, and a double-tap checks it. Each item is its own accessible element, reached by swiping. The indicator has no role, and screen readers pass over it.

### Keyboard

With a hardware keyboard, with iOS Full Keyboard Access or on Android:

| Key        | Does                                                       |
| ---------- | ---------------------------------------------------------- |
| Tab        | Moves to the next item, and Shift-Tab to the previous one  |
| Arrow keys | Move between items, on Android only, without checking them |
| Space      | Checks the focused item                                    |
| Enter      | Checks the focused item, on Android only                   |

Every item is its own stop: React Native delivers no arrow keys to views, so the control's single tab stop and its arrow keys, which check an item as they move, aren't built.
