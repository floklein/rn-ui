title: Autocomplete
description: Suggest text while someone types, without limiting what they can enter.

Use Autocomplete for a text field with helpful suggestions. Choosing one fills in the field, but any text is a valid value. It handles filtering, placing the list against the field and what screen readers hear. You provide the parts and styles.

<ComponentExample
  name="autocomplete/demo"
  caption="Type “man” and tap Mango to fill it in. You can also leave text that isn't in the list."
/>

## Installation

```bash
npm install @ui-sdk/react-native @ui-sdk/core
```

The suggestions render in the [`OverlayHost`](../installation#wrap-your-app) that wraps your app, so the keyboard stays up while they show; without one, they render in place and warn in development.

## Composition

Use the following composition to build an `Autocomplete`:

```text
Autocomplete
├── AutocompleteLabel
├── AutocompleteInput
└── AutocompleteContent
    ├── AutocompleteEmpty
    └── AutocompleteList
        ├── AutocompleteItem
        └── AutocompleteItem
```

`AutocompleteInput` renders a `TextInput`, `AutocompleteItem`, `AutocompleteTrigger` and `AutocompleteClear` a `Pressable`, `AutocompleteLabel`, `AutocompleteItemText` and `AutocompleteGroupLabel` a `Text`, and the other parts a `View`. Text inside a `Pressable` or `View` part goes in a `Text` you write. The content renders in the `OverlayHost`, so context from your own provider placed between `Autocomplete` and `AutocompleteContent` doesn't reach it: put it above your app's `OverlayHost` or inside the content. The library's own context does reach it.

## Usage

Import the parts and put them together. The content is placed for you, so give it a size and a look, not a position:

```tsx
import {
  Autocomplete,
  AutocompleteContent,
  AutocompleteInput,
  AutocompleteItem,
  AutocompleteLabel,
  AutocompleteList,
} from "@ui-sdk/react-native/autocomplete"
import { StyleSheet, Text } from "react-native"

function Example() {
  return (
    <Autocomplete>
      <AutocompleteLabel>Fruit</AutocompleteLabel>
      <AutocompleteInput placeholder="Type a fruit…" style={styles.input} />
      <AutocompleteContent style={styles.content}>
        <AutocompleteList>
          <AutocompleteItem value="Apple">
            <Text>Apple</Text>
          </AutocompleteItem>
          <AutocompleteItem value="Banana">
            <Text>Banana</Text>
          </AutocompleteItem>
        </AutocompleteList>
      </AutocompleteContent>
    </Autocomplete>
  )
}

const styles = StyleSheet.create({
  input: { minHeight: 44, paddingHorizontal: 12, borderWidth: 1 },
  content: { width: 240, padding: 4, backgroundColor: "#ffffff" },
})

export { Example }
```

A suggestion's label is its text, read from the `Text` inside it, or its `label` when it holds more than the words to match. Choosing it puts the label in the field.

## Autocomplete vs Combobox

Both filter a list as you type. They differ in what the value is.

- **Autocomplete**: the value is the text. Suggestions help fill it in, and anything typed is valid. Use it for a search box, an address or a free-form field.
- **Combobox**: the value is an option from the list. Use it for a country, an assignee or a set of labels.

## Disabled

A disabled field can't be edited and doesn't open. A read-only field shows its text but doesn't open or take changes; React Native reads a read-only field as disabled on Android and single-line iOS. A disabled suggestion can't fill in the field.

## Filter and Keywords

The default filter matches text anywhere in a suggestion. Use `"startsWith"` or `"fuzzy"` for a different match, a function for your own filter, or `false` for results a server already filtered. `keywords` adds searchable text without changing what goes in the field.

## Async Search

Use `filter={false}` when your server filters the suggestions. Connect `onValueChange` to your loader, and pass its items and status to `Autocomplete`. `useAsyncOptions` from `@ui-sdk/react-native/async-options` drops stale requests and loads the next page. `AutocompleteStatus` shows loading and result counts; without one, Autocomplete announces the count once typing pauses. `onLoadMore` runs when the highlight reaches the last result, not as the list scrolls.

## Search

The return key runs `onSubmit` with the text, or chooses the highlighted suggestion first. With `submitOnSelect`, choosing a suggestion submits it too, like a search box. The keyboard stays up after return; set `submitBehavior` on `AutocompleteInput` to change that, and `returnKeyType` to label the key.

## Long Lists

Cap the content's height with its state's `availableHeight` and put the list in a `ScrollView` with `keyboardShouldPersistTaps="handled"`, so the first tap on a suggestion chooses it instead of closing the keyboard.

## Placement

The content opens on `side` of the field, `"bottom"` by default, lined up with its start by `align`. It flips when there isn't room and shifts to stay on screen; `sideOffset`, 4 by default, sets the gap. It's placed before its first frame and measured again while open, so it follows the keyboard and a field in a scroll view. `anchor` places it against another view. `AutocompleteArrow` points at the field. [Popover](./popover#placement) describes placement in full.

<ComponentExample
  name="autocomplete/positioning"
  caption="Type “a”. The list opens above the card, lined up with its end."
/>

## Closing

Choosing a suggestion closes the list with the `"item-press"` reason, and the return key with `"input-commit"` when nothing is highlighted. It also closes when:

- something outside it is pressed, with `"outside-press"`;
- Android's back button or gesture is used, with `"back"`;
- VoiceOver's escape gesture, a two-finger Z, is made, with `"escape-key"`.

Set `dismissible={false}` to refuse those, and ask in `onDismissAttempt`. Focus leaving the field doesn't close the list on native.

## Focus

Focus stays in the field while the suggestions open and change, so the keyboard stays up. While it does, VoiceOver and TalkBack say the highlighted suggestion as typing moves it, where the web points `aria-activedescendant` at it. A screen reader's press on `AutocompleteTrigger` moves it to the first suggestion, and choosing one or the escape gesture moves it back to the field. The controller's `focus()` and a press on `AutocompleteLabel` start editing the field.

## Controlled

Use `value` with `onValueChange` to own the text, and `open` with `onOpenChange` to own the list. Call `details.cancel()` in a callback to refuse the change.

| Prop                   | On             | Receives                                                     |
| ---------------------- | -------------- | ------------------------------------------------------------ |
| `onValueChange`        | `Autocomplete` | `(value, details)`: the new text, and the [reason](#reasons) |
| `onOpenChange`         | `Autocomplete` | `(open, details)`: the new state, and the [reason](#reasons) |

| `onSubmit`             | `Autocomplete` | `(value, {})`: the text, when the return key submits it      |
| `onHighlight`          | `Autocomplete` | `(value, { index })`: the highlighted suggestion and its row |
| `onLoadMore`           | `Autocomplete` | `()`, when the highlight reaches the last suggestion         |
| `onDismissAttempt`     | `Autocomplete` | `({ reason })`, when a dismissal was refused                 |

## Accessibility

The field has the combobox role and an expanded state, which TalkBack can expand and collapse, and it's named by `AutocompleteLabel`, a [Field](./field)'s label or its own `aria-label`. TalkBack announces it as a combo box; React Native gives iOS no combo box trait, so VoiceOver reads it as a text field. Each suggestion is its own element, a button selected while it's highlighted; React Native has no option role. A separator and an icon are hidden from screen readers.

### Keyboard

With a hardware keyboard, with iOS Full Keyboard Access or on Android:

| Key    | Does                                                                                         |
| ------ | -------------------------------------------------------------------------------------------- |
| Tab    | Moves from the field to the suggestions and the other controls; Android skips a disabled one |
| Return | In the field, chooses the highlighted suggestion, or submits the text                        |
| Space  | Chooses a suggestion that has focus                                                          |

Arrow keys don't move the highlight from the field: React Native doesn't report them from a `TextInput`.
