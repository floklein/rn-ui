---
title: Select
description: Choose one value or several from a list placed against its trigger.
---

Use a Select when someone needs to choose from a set of options. It handles opening the list, placing it, selection and what screen readers hear. You provide the parts and styles.

<ComponentExample
  name="select/demo"
  caption="Tap Role and choose Editor. The list closes and the trigger shows your choice."
/>

## Installation

```bash
npm install @ui-sdk/react-native @ui-sdk/core
```

By default the list renders in a React Native `Modal`. With `modal={false}` it renders in the [`OverlayHost`](../installation#wrap-your-app) that wraps your app; without one, it renders in place and warns in development.

## Composition

Use the following composition to build a `Select`:

```text
Select
├── SelectLabel
├── SelectTrigger
│   └── SelectValue
└── SelectContent
    ├── SelectItem
    │   └── SelectItemIndicator
    └── SelectItem
```

`SelectTrigger`, `SelectItem`, `SelectSelectAll` and `SelectClear` render a `Pressable`, `SelectLabel`, `SelectValue`, `SelectItemText` and `SelectGroupLabel` a `Text`, `SelectInput` a `TextInput`, and the other parts a `View`. Text inside a `Pressable` or `View` part goes in a `Text` you write. The content renders in a `Modal` or in the `OverlayHost`, so context from your own provider placed between `Select` and `SelectContent` doesn't reach it: put it above your app's `OverlayHost` or inside the content. The library's own context does reach it.

## Usage

Import the parts and put them together. The content is placed for you, so give it a size and a look, not a position:

```tsx
import {
  Select,
  SelectContent,
  SelectItem,
  SelectLabel,
  SelectTrigger,
  SelectValue,
} from "@ui-sdk/react-native/select"
import { StyleSheet, Text } from "react-native"

function Example() {
  return (
    <Select placeholder="Select a role">
      <SelectLabel>Role</SelectLabel>
      <SelectTrigger style={styles.trigger}>
        <SelectValue />
      </SelectTrigger>
      <SelectContent style={styles.content}>
        <SelectItem value="viewer">
          <Text>Viewer</Text>
        </SelectItem>
        <SelectItem value="editor">
          <Text>Editor</Text>
        </SelectItem>
      </SelectContent>
    </Select>
  )
}

const styles = StyleSheet.create({
  trigger: { minHeight: 44, justifyContent: "center", paddingHorizontal: 12 },
  content: { width: 220, padding: 4, backgroundColor: "#ffffff" },
})

export { Example }
```

An item's label is its text, read from the `Text` inside it, or its `label` when the content holds more than the words to match. `SelectValue` shows the selected item's label, or the placeholder.

## Items as Data

Pass an array to `items` when your options come from data. A string is both the value and the label; use an object when they differ. `items` can also hold groups and separators, typed with `ListData`. Keeping the data on the root also makes labels known before the list opens.

## Disabled

A disabled select can't be opened or changed. A read-only select can be opened, but its value can't change. A disabled item can't be chosen; on Android it reads as disabled.

## Search

Add `SelectInput` inside `SelectContent` to filter the options, and put the items in `SelectList`. `SelectEmpty` shows while nothing matches, and groups with no match hide. `SelectItemText`'s state splits its text into `segments`, marking what the search matched, so you can render matches bold. Closing the list empties the search.

While focus stays in the search field, VoiceOver and TalkBack say the highlighted option as typing moves it, where the web points `aria-activedescendant` at it.

## Async Search

Use `filter={false}` when your server filters the options. Connect `query` and `onQueryChange` to your loader, and pass its items and status to `Select`. `useAsyncOptions` from `@ui-sdk/react-native/async-options` drops stale requests and loads the next page. `SelectStatus` shows loading and result counts; without one, Select announces the count once typing pauses. `onLoadMore` runs when the highlight reaches the last result, not as the list scrolls.

## Placement

The content opens on `side` of its trigger, `"bottom"` by default, lined up with its start by `align`. It flips when there isn't room and shifts to stay on screen; `sideOffset`, 4 by default, sets the gap. It's placed before its first frame and measured again while open, so it follows a trigger in a scroll view. `SelectArrow` points at the trigger. [Popover](./popover#placement) describes placement in full.

<ComponentExample
  name="select/positioning"
  caption="Pick a side, then tap Fruit."
/>

## Closing

Choosing an item closes a single select with the `"item-press"` reason. It also closes when:

- something outside it is pressed, with `"outside-press"`;
- Android's back button or gesture is used, with `"back"`;
- VoiceOver's escape gesture, a two-finger Z, is made, with `"escape-key"`.

Set `dismissible={false}` to refuse those, and ask in `onDismissAttempt`.

## Modal

By default the list renders in a `Modal`, which hides the rest of the screen from screen readers, and a press outside only closes it. `modal={false}` renders it in the `OverlayHost` instead: the screen stays reachable, and a press outside closes the list and still reaches what you pressed.

<ComponentExample
  name="select/modal"
  caption="Tap Status, then tap the counter behind the list. Pick Non-modal and try again: the press reaches the counter."
/>

## Focus

When the list opens from a screen reader, VoiceOver or TalkBack moves to the selected item, or the first one that can be chosen, or to the search field when there is one. When it closes, the screen reader moves back to the trigger. The controller's `focus()` moves it to the trigger, and a press on `SelectLabel` does too.

## Controlled

Use `value` with `onValueChange` to own the selection, and `open` with `onOpenChange` to own the list. A single value is `T | null`; with `multiple`, it's `T[]`. Call `details.cancel()` in a callback to refuse the change.

## Accessibility

The trigger has the combobox role and an expanded state, which TalkBack can expand and collapse, and it's named by `SelectLabel`, a [Field](./field)'s label or its own `aria-label`. The selected label is its accessibility value. TalkBack announces it as a combo box; React Native gives iOS no combo box trait, so VoiceOver reads its label, value and whether it's expanded. Each option is its own element, a button whose selected state is the committed value; React Native has no option role. A separator and an indicator are hidden from screen readers.

### Keyboard

With a hardware keyboard, with iOS Full Keyboard Access or on Android:

| Key   | Does                                                          |
| ----- | ------------------------------------------------------------- |
| Tab   | Moves through the controls, and through a list's options      |
| Space | Opens or closes the list from the trigger, or chooses an item |
| Enter | Does the same, on Android only                                |

Arrow keys, Home, End and typeahead don't move through the list: React Native doesn't report them.
