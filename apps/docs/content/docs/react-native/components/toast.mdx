A toast tells someone that something happened, like a saved change or a sent message, and goes away on its own. It can offer an action such as Undo, and VoiceOver and TalkBack announce it without moving to it.

<ComponentExample

  caption="Tap Create Event. Tap Undo, swipe the toast away, or wait for it to close. Undo logs Event removed."
/>

## Installation

```bash
npm install @ui-sdk/react-native @ui-sdk/core
```

Toasts render in the [`OverlayHost`](../installation#wrap-your-app) that wraps your app. Without one, a region renders in place and warns in development.

## Composition

Use the following composition to build a `ToastRegion`:

```text
ToastRegion
├── Toast
│   ├── ToastTitle
│   ├── ToastDescription
│   ├── ToastAction
│   └── ToastClose
└── Toast
    ├── ToastTitle
    └── ToastDescription
```

`ToastRegion` and `Toast` render a `View`, `ToastTitle` and `ToastDescription` a `Text`, and `ToastAction` and `ToastClose` a `Pressable`. The region renders one `Toast` for each toast in its queue, newest first, through its children function. Empty title, description and action parts show the text from the toast's data.

The region renders in the topmost open host, so a toast shows above a modal dialog that is open, and moves back when the dialog closes. Context from your own provider placed between `ToastRegion` and the screen doesn't reach the toasts: put it above your app's `OverlayHost` or inside each toast. The library's own context does reach them.

## Usage

Import the parts and put them together, then call `toast()` when an action finishes:

```tsx
import {
  Toast,
  ToastDescription,
  ToastRegion,
  ToastTitle,
  toast,
} from "@ui-sdk/react-native/toast"
import { Pressable, StyleSheet, Text } from "react-native"

function Example() {
  return (
    <>
      <Pressable
        role="button"
        onPress={() =>
          toast("Event created", { description: "Friday at 10:00 AM" })
        }
      >
        <Text>Create Event</Text>
      </Pressable>
      <ToastRegion>
        {() => (
          <Toast style={styles.toast}>
            <ToastTitle />
            <ToastDescription />
          </Toast>
        )}
      </ToastRegion>
    </>
  )
}

const styles = StyleSheet.create({
  toast: { margin: 16, padding: 16, backgroundColor: "#ffffff" },
})

export { Example }
```

`toast()` works from anywhere, not only from components, and returns the toast's id. Place the region once, or let `OverlayHost` render it. Without children, it renders each toast's title, description, action and cancel button as a plain white card.

The examples below each call `createToaster()` for a queue of their own and pass it to their region as `toaster`, so their toasts don't mix.

## Types

`toast.success`, `.info`, `.warning`, `.error` and `.loading` set the toast's type, which the toast's state holds as `type` for an icon or a color. Errors are announced right away and other types wait for what the screen reader is saying; set `priority` to change that. A loading toast stays until it's updated or dismissed.

## Position

Set the region's `side` to `top` or `bottom`, and `align` to `start`, `center` or `end`. Start and end follow the app's direction. The region keeps clear of the `insets` you pass to `OverlayHost`, and a bottom region sits above the on-screen keyboard. A toast can be swiped toward the side and, unless it's centered, toward the end it's aligned to.

## Swipe to Dismiss

A toast follows a finger that moves it a few points toward a direction it can be swiped to, also when the finger started on its action or close button. Far enough, or fast enough, dismisses it with the `"swipe"` reason; otherwise it goes back. A toast with `dismissible: false` can't be swiped.

The toast's state holds where the swipe has moved it, `swipeX` and `swipeY`, so move it with a transform. Its timer waits while it's swiped.

```tsx
<Toast
  style={(state) => [
    styles.toast,
    {
      transform: [{ translateX: state.swipeX }, { translateY: state.swipeY }],
    },
  ]}
>
```

## Stacking

`maxVisible` limits how many toasts show at once, three by default; the rest wait in the queue, and their timers start when they show. Touch has no hover, so the stack is expanded only when you set `expanded`. Each toast's state has its `index`, 0 for the newest, to lay out a collapsed stack.

## Duration

Set `duration` in milliseconds, on the toaster or on one toast, or `Infinity` for a toast that stays until it's dismissed. The default is five seconds. Timers pause while a toast is swiped and while the app is in the background. While a screen reader runs, a toast with an action or a close button waits, as [Accessibility](#accessibility) explains.

## Update and Dismiss

Keep the id `toast()` returns to update or dismiss that toast, or pass your own `id`. `toast.update()` returns whether the toast was still there, and `toast.dismiss()` without an id closes every toast.

## Accessibility

VoiceOver and TalkBack announce each toast once, from its title and description, without moving to it: politely by default, so it waits for what the screen reader is saying, and right away for errors. Only text is read: a title or description that isn't a string isn't announced. Keep messages short, and use `duration: Infinity` for one that has to stay available. While a screen reader runs, a toast with an action or a close button waits until one of its buttons runs, your app dismisses it or the screen reader stops, so there's time to reach its buttons; other toasts still close after their duration. VoiceOver's escape gesture dismisses a toast, and on Android the toast is one element, its title and description, with a Dismiss action TalkBack offers; its buttons stay elements of their own. A toast with `dismissible: false` has neither. The action is labelled "Dismiss": to translate it, render your own `Toast` and pass `accessibilityActions={[{ name: "dismiss", label: "Ignorer" }]}`. The action and close buttons are buttons, and an action with an `href` is a link.

On native a toast leaves at once: it has no exit animation. A focused toast can't be dismissed with a key: give a toast that stays a close button.

### Keyboard

With a hardware keyboard, with iOS Full Keyboard Access or on Android:

| Key   | Does                               |
| ----- | ---------------------------------- |
| Tab   | Moves through the toasts' buttons  |
| Space | Presses the action or close button |
| Enter | Does the same, on Android only     |
