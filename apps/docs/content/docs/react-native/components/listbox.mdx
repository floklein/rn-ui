title: Listbox

Use a Listbox when the choices should stay in view. It handles selection, disabled and read-only options, and what screen readers hear. You provide the parts and styles.

/>

## Installation

```bash
npm install @ui-sdk/react-native @ui-sdk/core
```

## Composition

Use the following composition to build a `Listbox`:

```text
Listbox
├── ListboxItem
│   └── ListboxItemIndicator
└── ListboxItem
    └── ListboxItemIndicator
```

`ListboxItem` renders a `Pressable`, `ListboxGroupLabel` a `Text`, and the other parts a `View`. Text inside a `Pressable` or `View` part goes in a `Text` you write. Give each option a unique value. `ListboxItemIndicator` shows its content while its option is selected.

## Usage

Import the parts and put them together:

```tsx
import {
  Listbox,
  ListboxItem,
  ListboxItemIndicator,
} from "@ui-sdk/react-native/listbox"
import { StyleSheet, Text } from "react-native"

function Example() {
  return (
    <Listbox aria-label="Toppings" defaultValue="basil">
      <ListboxItem value="basil" style={styles.item}>
        <Text>Basil</Text>
        <ListboxItemIndicator>
          <Text>✓</Text>
        </ListboxItemIndicator>
      </ListboxItem>
      <ListboxItem value="olive" style={styles.item}>
        <Text>Olive</Text>
        <ListboxItemIndicator>
          <Text>✓</Text>
        </ListboxItemIndicator>
      </ListboxItem>
    </Listbox>
  )
}

const styles = StyleSheet.create({
  item: {
    minHeight: 44,
    flexDirection: "row",
    alignItems: "center",
    justifyContent: "space-between",
    paddingHorizontal: 12,
  },
})

export { Example }
```

An option's label is its text, read from the `Text` inside it, or its `label` when the content holds more than its words.

## Multiple

Add `multiple` to select several options. The value becomes an array; a single list uses one value or `null`. A press toggles an option. Shift ranges and Ctrl or ⌘ with A don't exist on native, where nothing reports those keys; the controller's `selectAll()` selects every enabled option.

## Styling

Style each part with a function of its state, like `(state) => [styles.item, state.selected && styles.selected]`. `highlighted` is true while an option has keyboard focus, which React Native reports on Android; a touch or a screen reader doesn't highlight. Each part receives the fields listed under [Part State](#part-state).

## Accessibility

Follows the [WAI-ARIA listbox pattern](https://www.w3.org/WAI/ARIA/apg/patterns/listbox/), translated to React Native's accessibility props. React Native has no option role: each option is a button whose selected state says whether it's selected, its own accessible element reached by swiping, and a double-tap selects it, or toggles it with `multiple`. A separator and an indicator are hidden from screen readers.

The list's own name, from `aria-label` or a [Field](./field)'s label, sits on a container, so it reaches no screen reader; name the list with a visible heading or label beside it. A press on a Field's label moves the screen reader to the option that holds the list's tab stop.

### Keyboard

With a hardware keyboard, with iOS Full Keyboard Access or on Android:

| Key   | Does                                                                       |
| ----- | -------------------------------------------------------------------------- |
| Tab   | Moves to the next option, and Shift-Tab back; Android skips a disabled one |
| Space | Selects the focused option, or toggles it with `multiple`                  |
| Enter | Does the same, on Android only                                             |

Every option is its own stop: React Native delivers no arrow keys, Home, End or typing to views, so the list's single tab stop, its arrow keys, typeahead and Shift ranges aren't built.
