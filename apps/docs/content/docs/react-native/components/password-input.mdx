A Password Input is a `TextInput` with secure entry and a button that shows and hides what's typed. It asks for the right password to autofill, turns off correction and capitals, and reports why the password was shown or hidden.

/>

## Installation

```bash
npm install @ui-sdk/react-native @ui-sdk/core
```

## Composition

Use the following composition to build a `PasswordInput`:

```text
PasswordInput
├── PasswordInputControl
└── PasswordInputToggle
```

`PasswordInput` holds the value and visibility state, and renders a `Pressable` that isn't an accessible element itself: tapping its own text or icons starts editing the field. `PasswordInputControl` renders the `TextInput`, with `secureTextEntry` while the password is hidden. `PasswordInputToggle` renders a `Pressable` with the toggle button role.

Put `required`, `disabled`, `readOnly` and `autoComplete` on `PasswordInput`. Put other `TextInput` props, such as `placeholder` or `onSubmitEditing`, on `PasswordInputControl`.

## Usage

Import the parts and put them together:

```tsx
import {
  PasswordInput,
  PasswordInputControl,
  PasswordInputToggle,
} from "@ui-sdk/react-native/password-input"
import { Text } from "react-native"

function Example() {
  return (
    <PasswordInput>
      <PasswordInputControl aria-label="Password" />
      <PasswordInputToggle aria-label="Show password">
        {(state) => <Text>{state.visible ? "Hide" : "Show"}</Text>}
      </PasswordInputToggle>
    </PasswordInput>
  )
}

export { Example }
```

## New Password

Use `autoComplete="new-password"` on the root when creating or changing a password, so iOS and Android offer to generate and save one. The default is `current-password` for signing in.

The example derives a checklist from the current value. Those rules belong to the example; the component does not impose a password policy.

## Disabled and Read Only

Set `disabled` on the root to disable both the field and the toggle. Screen readers announce both as dimmed or disabled, and Android's Tab skips them.

<ComponentExample
  name="password-input/disabled"

A `readOnly` field can't be edited, and its toggle still shows and hides it. React Native has no read-only field that stays enabled, so screen readers announce the field as dimmed or disabled, and Android's Tab skips it.

  name="password-input/read-only"

`required` stays in the state, for your styles and labels. It isn't announced.

## Hiding While Editing on iOS

On iOS, a secure field erases its text when typing resumes after it was hidden again, as every iOS password field does. Showing the password keeps the text, and so does Android.

## Forms and Caps Lock

A native view takes part in no form, so there's no `name`, `form`, submission or reset: read the value from `onValueChange` or the controller. `TextInput` reports no modifier keys, so the `capsLock` state stays `false`.

## Styling

Style each part with a function of its state, like `(state) => [styles.toggle, state.visible && styles.shown]`. Every part receives the fields listed under [Part State](#part-state). A second argument, `{ pressed, hovered, focused }`, says whether a part is pressed, and whether the field is being edited, in `focused`.

## Accessibility

There's no WAI-ARIA pattern for a password field. The field is a secure `TextInput`, its own accessible element, named by an `aria-label`. The toggle follows the [WAI-ARIA button pattern](https://www.w3.org/WAI/ARIA/apg/patterns/button/) as a toggle button: on Android TalkBack reads it as a toggle button that's on or off, and on iOS VoiceOver reads it as a button that's checked or unchecked. Name it by what it does, such as “Show password”, and keep that name the same.

A tap on the toggle leaves the field editing, with the keyboard up. Inside a `ScrollView`, set `keyboardShouldPersistTaps="handled"` so the first tap reaches the toggle instead of closing the keyboard.

### Keyboard

With a hardware keyboard, with iOS Full Keyboard Access or on Android:

| Key   | Does                                                                                               |
| ----- | -------------------------------------------------------------------------------------------------- |
| Tab   | Moves from the field to the toggle, and Shift-Tab back                                             |
| Space | Shows or hides the password on the toggle, which keeps focus                                       |
| Enter | On the toggle, shows or hides the password, on Android only; in the field, calls `onSubmitEditing` |
