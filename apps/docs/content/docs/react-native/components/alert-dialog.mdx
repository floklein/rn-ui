Use an alert dialog to ask before something that can't be undone, like deleting a project.

  name="alert-dialog/basic"

/>

## Installation

```bash
npm install @ui-sdk/react-native @ui-sdk/core
```

## Composition

Alert Dialog has [Dialog](./dialog)'s parts, named `AlertDialog`, `AlertDialogTrigger`, `AlertDialogBackdrop`, `AlertDialogContent`, `AlertDialogTitle`, `AlertDialogDescription` and `AlertDialogClose`, rendered the same way, in one `Modal`. It is always modal, and a press on its backdrop never closes it: `onDismissAttempt` hears it instead. Android's back and VoiceOver's escape gesture close it, unless `dismissible` is `false`.

## Usage

```tsx
import {
  AlertDialog,
  AlertDialogBackdrop,
  AlertDialogClose,
  AlertDialogContent,
  AlertDialogTitle,
  AlertDialogTrigger,
} from "@ui-sdk/react-native/alert-dialog"
import { Text } from "react-native"

function Example() {
  return (
    <AlertDialog onOpenChange={(open, { returnValue }) => {}}>
      <AlertDialogTrigger>
        <Text>Delete Project</Text>
      </AlertDialogTrigger>
      <AlertDialogBackdrop />
      <AlertDialogContent>
        <AlertDialogTitle>Delete this project?</AlertDialogTitle>
        <AlertDialogClose>
          <Text>Cancel</Text>
        </AlertDialogClose>
        <AlertDialogClose value="confirm">
          <Text>Delete</Text>
        </AlertDialogClose>
      </AlertDialogContent>
    </AlertDialog>
  )
}

export { Example }
```

## Focus

Opened with a touch, the alert dialog asks the screen reader to move to its title. Opened another way, like from a controller or by a screen reader, it moves to its first Close part, the least destructive answer, so put Cancel first.

## Async Actions

A Close part's `action` runs before the alert dialog closes. A Promise it returns keeps the dialog open while it runs: the part's state has `pending`, screen readers hear `pendingAnnouncement` after a second, and only the controller closes the dialog. A rejection keeps it open and puts the reason in the part's `error`.

## Confirm

`createConfirm()` asks a question from code and resolves with the answer: `if (await confirm({ name })) remove(name)`. Pass `confirm.controller` to your own `AlertDialog`, and give the agreeing Close part `value="confirm"`. Questions asked while one is open wait their turn.

## Nested

An alert dialog opened inside another renders inside its `Modal`, such as a second confirmation before something can't be undone. Android's back button closes the topmost one and returns focus to its trigger. To close both once the last question is answered, control the outer alert dialog and close it when the inner one closes with `returnValue` `"confirm"`.

## Accessibility

The alert dialog follows the [WAI-ARIA alert dialog pattern](https://www.w3.org/WAI/ARIA/apg/patterns/alertdialog/) as [Dialog](./dialog#accessibility) does: in a `Modal` that hides the rest of the screen, named by its title, which has the header role.
