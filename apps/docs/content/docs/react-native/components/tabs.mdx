Use Tabs when several views share the same space, such as settings sections or a preview and its source. Each tab opens the panel with the same value.

/>

## Installation

```bash
npm install @ui-sdk/react-native @ui-sdk/core
```

## Composition

Use the following composition to build a `Tabs`:

```text
Tabs
├── TabsList
│   ├── TabsTab
│   ├── TabsTab
│   └── TabsIndicator
├── TabsPanel
└── TabsPanel
```

`TabsTab` renders a `Pressable` with the tab role and its selected state. `Tabs`, `TabsList`, `TabsIndicator` and `TabsPanel` render a `View`. Give each tab and its panel the same unique `value`, and the list an `aria-label`. Set `defaultValue` to choose the initial tab; otherwise, the first enabled tab is selected once the tabs mount.

## Usage

Import the parts and put them together. Text inside a tab goes in a `Text`, and names the tab:

```tsx
import { Tabs, TabsList, TabsPanel, TabsTab } from "@ui-sdk/react-native/tabs"
import { Text } from "react-native"

function Example() {
  return (
    <Tabs defaultValue="account">
      <TabsList aria-label="Settings">
        <TabsTab value="account">
          <Text>Account</Text>
        </TabsTab>
        <TabsTab value="password">
          <Text>Password</Text>
        </TabsTab>
      </TabsList>
      <TabsPanel value="account">
        <Text>Manage your profile.</Text>
      </TabsPanel>
      <TabsPanel value="password">
        <Text>Choose a new password.</Text>
      </TabsPanel>
    </Tabs>
  )
}

export { Example }
```

## Disabled

Add `disabled` to a tab to prevent selection. Screen readers still reach it and announce it as dimmed or disabled.

<ComponentExample
  name="tabs/disabled"
  caption="Tap Reports. It stays unselected, and the current panel stays."

On Android the disabled state disables the view, so Tab skips a disabled tab.

## Indicator

`TabsIndicator` marks the selected tab. Render it inside `TabsList`: its state holds the selected tab's box in the list, measured from the layouts of the list and the tabs placed in it. Position it absolutely with those fields to draw a marker that follows the selection. It measures again when a tab or the list is laid out again.

```tsx
<TabsIndicator
  style={(state) => ({
    position: "absolute",
    left: state.activeTabLeft,
    top: state.activeTabTop,
    width: state.activeTabWidth,
    height: state.activeTabHeight,
  })}
/>
```

The fields are unset until the list and the selected tab have been laid out. Render the indicator before the tabs to draw it behind them.

## Animation

A panel leaves through `onExit`. When another tab is selected, the panel calls `onExit` with a `done` function and stays on screen until you call it, or until two seconds pass. Meanwhile it takes no touches and screen readers skip it. Without `onExit`, it unmounts at once, or hides with `keepMounted`. A panel's state also has `startingStyle`, true for its first frame after it appears, and `endingStyle`, true while it leaves.

```tsx
const opacity = useRef(new Animated.Value(1)).current

<TabsPanel
  value="activity"
  onExit={(done) =>
    Animated.timing(opacity, {
      toValue: 0,
      duration: 150,
      useNativeDriver: true,
    }).start(done)
  }
  render={<Animated.View style={{ opacity }} />}
/>
```

`LayoutAnimation` animates the indicator and the panels together without either: configure it in `onValueChange`, as this example does.

## Controlled

Use `value` and `onValueChange` to own the selected tab. Call `details.cancel()` in the callback to keep the current tab. `onValueChange` doesn't run for the initial selection. A [controller](#controller) from `createTabsController()` selects a tab from anywhere, and its `focus()` moves VoiceOver's or TalkBack's focus to the selected tab.

<ComponentExample
  name="tabs/controlled"
  caption="Tap Drafts, then Show Sent Mail. The log shows each new value with its reason."
/>

The callback receives the new value and `details`, whose `reason` is `"item-press"`, `"item-removed"` or `"imperative"`, and whose `source` is `"touch"`, or `"virtual"` while a screen reader runs.

## Accessibility

Tabs follow the [WAI-ARIA tabs pattern](https://www.w3.org/WAI/ARIA/apg/patterns/tabs/), translated to React Native's accessibility props: the list has the tab list role, and each tab the tab role with its selected and disabled state, so VoiceOver and TalkBack announce which tab is selected, and a double-tap selects one. Each tab is its own accessible element, reached by swiping. A panel is a `View` with no role, since React Native has no tab panel role.

### Keyboard

With a hardware keyboard, with iOS Full Keyboard Access or on Android:

| Key        | Does                                                         |
| ---------- | ------------------------------------------------------------ |
| Tab        | Moves to the next control, and Shift-Tab to the previous one |
| Arrow keys | Move between controls, on Android only                       |
| Space      | Selects the focused tab                                      |
| Enter      | Selects the focused tab, on Android only                     |

Every tab is its own stop: React Native delivers no arrow keys to views, so the list's single tab stop, arrow keys, Home and End aren't built.
