Use a popover for a small task next to what it's about, like sharing a link or setting a status, when the user stays on the screen.

<ComponentExample
  name="popover/basic"
  caption="Tap Share. The popover opens below the button, and VoiceOver or TalkBack moves to its title. Tap Cancel, anywhere outside it or Android's back to close it."
/>

## Installation

```bash
npm install @ui-sdk/react-native @ui-sdk/core
```

A non-modal popover renders in the [`OverlayHost`](../installation#wrap-your-app) that wraps your app. Without one, it renders in place and warns in development.

## Composition

Use the following composition to build a `Popover`:

```text
Popover
├── PopoverTrigger
└── PopoverContent
    ├── PopoverArrow
    ├── PopoverTitle
    ├── PopoverDescription
    └── PopoverClose
```

`PopoverTrigger` and `PopoverClose` render a `Pressable`, `PopoverContent` and `PopoverArrow` a `View`, and `PopoverTitle` and `PopoverDescription` a `Text`. The content renders in the `OverlayHost`, or in a `Modal` when it's modal, so context from your own provider placed between `Popover` and `PopoverContent` doesn't reach it: put it above your app's `OverlayHost` or inside the content. The library's own context does reach it.

## Usage

Import the parts and put them together. The content is placed for you, so give it a size and a look, not a position:

```tsx
import {
  Popover,
  PopoverClose,
  PopoverContent,
  PopoverTitle,
  PopoverTrigger,
} from "@ui-sdk/react-native/popover"
import { StyleSheet, Text } from "react-native"

function Example() {
  return (
    <Popover>
      <PopoverTrigger>
        <Text>Share</Text>
      </PopoverTrigger>
      <PopoverContent style={styles.content}>
        <PopoverTitle>Share this document</PopoverTitle>
        <PopoverClose>
          <Text>Done</Text>
        </PopoverClose>
      </PopoverContent>
    </Popover>
  )
}

const styles = StyleSheet.create({
  content: { width: 280, padding: 16, backgroundColor: "#ffffff" },
})

export { Example }
```

## Placement

The content opens on `side` of its trigger, `"bottom"` by default, and lines up with it by `align`, `"center"` by default. It flips to the other side when there isn't room and shifts along the trigger to stay on screen. `sideOffset` sets the gap, `alignOffset` shifts it along the trigger and `collisionPadding` keeps it away from the edges.

The content's position is absolute in the host it renders in, set from measurements taken before its first frame. While it's open it measures again, every frame while something moves and twice a second otherwise, so it follows a trigger in a scroll view. The space it may use leaves out the `insets` you pass to `OverlayHost` and the on-screen keyboard, counted once.

```tsx
<PopoverContent
  style={(state) => [styles.content, { maxHeight: state.availableHeight }]}
>
```

## Anchor

`anchor` places the content against something other than its trigger: a view, like a ref's `current`, or a point in window coordinates, like a touch's `pageX` and `pageY`. A controller's `open({ anchor })` does the same for one open.

## Arrow

`PopoverArrow` is placed along the content's edge facing the trigger, pointing at the trigger's center and kept `arrowPadding` from the corners. Its state's `side` says which edge, so you can turn it. When the trigger's center is past a corner, `arrowClamped` is true.

## Closing

A press on a Close part closes the popover with the `"close-press"` reason. It also closes when:

- something outside it is pressed, with `"outside-press"`;
- Android's back button or gesture is used, with `"back"`;
- VoiceOver's escape gesture, a two-finger Z, is made, with `"escape-key"`.

Set `dismissible={false}` to refuse those, and ask in `onDismissAttempt`.

<ComponentExample
  name="popover/draft"

## Modal

By default a popover is non-modal: the screen stays usable, and a press outside closes the popover and still reaches what you pressed. `modal` renders it in a React Native `Modal` instead, which hides the rest of the screen from screen readers, and a press outside only closes it. The content is still placed beside its trigger.

<ComponentExample
  name="popover/modal"

## Focus

When the popover opens from a screen reader, it moves VoiceOver or TalkBack to its title. `initialFocus="content"` moves to the content instead, and `"none"` leaves the screen reader where it is. When it closes, the screen reader moves back to the trigger, unless `finalFocus` is `"none"`.

## Animation

The content leaves through `onExit`, as in [Dialog](./dialog#animation): it stays on screen until you call `done`, or two seconds pass. Its state's `transformOrigin` is the point facing the trigger, for a scale that grows out of it.

## Accessibility

The trigger is a button with an expanded state, which TalkBack can expand and collapse. The title has the header role and names the popover; React Native has no dialog role, so screen readers announce the title, not "dialog". A non-modal popover leaves the rest of the screen reachable; a modal one's `Modal` hides it. The arrow is hidden from screen readers.

### Keyboard

With a hardware keyboard, with iOS Full Keyboard Access or on Android:

| Key   | Does                                                                  |
| ----- | --------------------------------------------------------------------- |
| Tab   | Moves through the controls                                            |
| Space | Opens or closes the popover from the trigger, or presses a Close part |
| Enter | Does the same, on Android only                                        |
