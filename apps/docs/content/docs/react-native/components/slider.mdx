Use a slider to pick a number or a range along a scale, like a volume or a price range, by dragging a thumb or with a screen reader's adjust gestures.

/>

## Installation

```bash
npm install @ui-sdk/react-native @ui-sdk/core
```

## Composition

Use the following composition to build a `Slider`:

```text
Slider
├── SliderValue
└── SliderControl
    └── SliderTrack
        ├── SliderIndicator
        └── SliderThumb
```

A control takes the touches around the track. Put a thumb on that track for each value.

- **Slider** holds the value and renders a `View` around the thumbs.
- **SliderControl** is where touches land, a `View`. A touch moves the nearest thumb there and starts a drag. Give it some height around a thin track, like 44 points.
- **SliderTrack** is the rail the thumbs move along, a `View`. Thumbs and the indicator are placed in percentages of it, so give it a size.
- **SliderIndicator** fills the track up to a single thumb, or between the first and last thumb of a range.
- **SliderThumb** is what you drag, a `View`. Give each one a size. It holds the element screen readers adjust, which reaches 12 points past the thumb on every side.
- **SliderValue** shows the formatted value in a `Text`, and a range joined with an en dash. It's optional, and hidden from screen readers, since each thumb says its own value.

A single thumb is named by a `FieldLabel` in a `Field`, or by `aria-label` on the thumb. In a range, give each thumb its own `aria-label`, like "Minimum price".

## Usage

Import the parts and put them together. Give the parts their sizes and colors with styles:

```tsx
import {
  Slider,
  SliderControl,
  SliderIndicator,
  SliderThumb,
  SliderTrack,
  SliderValue,
} from "@ui-sdk/react-native/slider"
import { StyleSheet } from "react-native"

function Example() {
  return (
    <Slider defaultValue={50}>
      <SliderValue />
      <SliderControl style={styles.control}>
        <SliderTrack style={styles.track}>
          <SliderIndicator style={styles.indicator} />
          <SliderThumb aria-label="Volume" style={styles.thumb} />
        </SliderTrack>
      </SliderControl>
    </Slider>
  )
}

const styles = StyleSheet.create({
  control: { width: 240, height: 44, justifyContent: "center" },
  track: { height: 4, backgroundColor: "#d4d4d8" },
  indicator: { backgroundColor: "#18181b" },
  thumb: {
    width: 20,
    height: 20,
    borderRadius: 10,
    backgroundColor: "#18181b",
  },
})

export { Example }
```

## Inside a Scroll View

A drag keeps its touch from a scroll view around it. On Android that's enough. On iOS, a `ScrollView` that scrolls along the slider's axis, like a horizontal slider in a horizontal `ScrollView`, still scrolls while the thumb moves, since React Native stops a scroll view only for a touch held by a view above it, not inside it. Turn its scrolling off for the length of the drag: set `dragging` from the control's responder events and pass `scrollEnabled={!dragging}`.

```tsx
const [dragging, setDragging] = useState(false)

return (
  <ScrollView horizontal scrollEnabled={!dragging}>
    <Slider defaultValue={50}>
      <SliderControl
        onResponderGrant={() => setDragging(true)}
        onResponderRelease={() => setDragging(false)}
        onResponderTerminate={() => setDragging(false)}
        style={styles.control}
      >
        <SliderTrack style={styles.track}>
          <SliderIndicator style={styles.indicator} />
          <SliderThumb aria-label="Balance" style={styles.thumb} />
        </SliderTrack>
      </SliderControl>
    </Slider>
  </ScrollView>
)
```

The grant runs only when the control takes the touch, so a disabled slider leaves the scroll view alone. A scroll view across the slider's axis, like a vertical `ScrollView` around a horizontal slider, needs nothing. Every other drag works the same way: pass the three handlers to the part you drag.

## Controlled

Pass `value` and `onValueChange` to control the slider. The value keeps its shape: a number stays a number and an array stays an array. Every change carries a [reason](#reasons), like `drag` or `track-press`, and `details.thumb` says which thumb moved. Call `details.cancel()` to keep the current value.

<ComponentExample
  name="slider/controlled"
  caption="Drag either Temperature thumb to log the range and its reason. Reset sets the value from outside."
/>

## Step and Bounds

`min` and `max` set the bounds, 0 and 100 by default, and `step` sets how far one step moves, counted from `min`. Decimal steps avoid floating-point drift, so a 0.1 step can reach 0.3 cleanly. When the steps from `min` don't land on `max`, the highest step below it is the end.

<ComponentExample
  name="slider/step"
  caption="Move Year in steps of five, and Opacity in steps of 0.05."
/>

## Large Step

`largeStep` is how far Page Up, Page Down and Shift with an arrow key move a thumb on the web. React Native delivers no keys to views, so on native it changes nothing: a drag lands on any step, and a screen reader moves one `step` at a time.

<ComponentExample

## Format and Locale

`format` takes `Intl.NumberFormat` options, like `{ style: "currency", currency: "USD" }` or `{ style: "percent" }`, or a function of the value. It sets what `SliderValue` shows and what screen readers announce for each thumb, while the value stays a plain number. `locale` sets separators, digits and symbol placement. Without it, the slider formats in the device's language, as `Intl` reports it.

<ComponentExample
  name="slider/format"
  caption="Adjust Budget, Opacity, Weight, Duration and Preis to compare currency, a percentage, a unit, a custom function and German formatting."
/>

## Saving on Commit

`onValueChange` runs on every step of a drag. `onValueCommit` runs once, when the touch that changed the value lifts, or when a screen reader adjusts it. Use the commit callback to save once per interaction. A touch that doesn't change the value commits nothing, and neither does a drag taken away, like by a system gesture: the value goes back to where it started.

<ComponentExample
  name="slider/commit"
  caption="Drag Brightness and lift your finger. The value is logged once."
/>

## Controller

A controller, from `createSliderController()`, moves the slider from anywhere with `setValue()`, reads it with `getValue()` and moves a screen reader's focus to a thumb with `focus()`. Values set through it are clamped, snapped to the step and sorted, and reported with the `imperative` reason.

<ComponentExample
  name="slider/controller"
  caption="Use Mute, Louder and Focus to operate Volume from outside the slider. Each change is logged with the imperative reason, and Read logs the value."
/>

## Forms

A native view takes part in no form, so the slider has no `name` or `form` prop and renders no hidden input. Read the value from `onValueChange`, `onValueCommit` or a controller. `required` stays in the state for your styles and labels.

## Read-Only

Set `readOnly` to keep the slider reachable by screen readers, while drags and their adjustments leave its value alone.

```tsx
<Field>
  <FieldLabel>Storage</FieldLabel>
  <Slider defaultValue={50} readOnly>
    <SliderControl style={styles.control}>
      <SliderTrack style={styles.track}>
        <SliderIndicator style={styles.indicator} />
        <SliderThumb style={styles.thumb} />
      </SliderTrack>
    </SliderControl>
  </Slider>
  <FieldDescription>Set by your plan.</FieldDescription>
</Field>
```

## Styling

Parts are unstyled, apart from the positions they need: thumbs and the indicator are placed absolutely along the track, in percent. Give the control some height around a thin track, the track a size and a background, and each thumb a size.

Style each part with a function of its state, like `(state) => [styles.thumb, state.dragging && styles.dragging]`. Each part receives the fields listed under [Part State](#part-state), and a second argument, `{ pressed, hovered, focused }`.

## Accessibility

The slider follows the [WAI-ARIA slider pattern](https://www.w3.org/WAI/ARIA/apg/patterns/slider/), and the [multi-thumb slider pattern](https://www.w3.org/WAI/ARIA/apg/patterns/slider-multithumb/) for ranges, translated to React Native's accessibility props. Each thumb is its own element with the `adjustable` role, named by a `FieldLabel`, a [Label](./label) for the slider's `id` or its own `aria-label`, and says its value as `format` writes it. VoiceOver adjusts it with a swipe up or down, and TalkBack with its adjust gestures: each moves one `step` and commits at once.

### Keyboard

With a hardware keyboard, with iOS Full Keyboard Access or on Android, Tab moves through the thumbs in order. React Native delivers no arrow keys, Page Up, Page Down, Home or End to views, so a keyboard can't move a thumb.
