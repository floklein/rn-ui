## Installation

```bash
npm install @ui-sdk/react-native @ui-sdk/core
```

## Composition

Use the following composition to build a `Collapsible`:

```text
Collapsible
├── CollapsibleTrigger
└── CollapsiblePanel
```

`CollapsibleTrigger` renders a `Pressable` with the button role, expanded while the panel is open. `Collapsible` and `CollapsiblePanel` render a `View`. Put other content around them, like a heading or a summary that always shows.

## Usage

Import the parts and put them together. Text inside the trigger goes in a `Text`, and names it:

```tsx
import {
  Collapsible,
  CollapsiblePanel,
  CollapsibleTrigger,
} from "@ui-sdk/react-native/collapsible"
import { Text } from "react-native"

function Example() {
  return (
    <Collapsible>
      <CollapsibleTrigger>
        <Text>Order details</Text>
      </CollapsibleTrigger>
      <CollapsiblePanel>
        <Text>2 × Linen shirt</Text>
      </CollapsiblePanel>
    </Collapsible>
  )
}

export { Example }
```

## Disabled

Set `disabled` on the root to stop its trigger from opening or closing the panel. Screen readers still reach the trigger and announce it as dimmed or disabled. On Android the disabled state disables the view, so Tab skips it.

```tsx
<Collapsible disabled>
  <CollapsibleTrigger>
    <Text>Gift options</Text>
  </CollapsibleTrigger>
  <CollapsiblePanel>
    <Text>Add a gift message and wrapping.</Text>
  </CollapsiblePanel>
</Collapsible>
```

## Keep Mounted

Panels unmount when they close. Set `keepMounted` on the panel to keep it mounted and hidden, so a field keeps what you typed into it. Native has no find in page, so `hiddenUntilFound` only keeps the panel mounted, like `keepMounted`.

## Controlled

Pass `open` and update it in `onOpenChange`. Call `details.cancel()` in the callback to cancel the change.

For a button elsewhere on the screen, create a [controller](#controller) with `createCollapsibleController()` and pass it as `controller`. Its `focus()` moves VoiceOver's or TalkBack's focus to the trigger. Create one controller per mounted collapsible.

<ComponentExample
  name="collapsible/controlled"
  caption="Open Recovery codes with Toggle or its trigger, then tap Done. The log shows each change and its reason."
/>

The callback receives the new state and `details`, whose `reason` is `"trigger-press"` or `"imperative"`, and whose `source` is `"touch"`, or `"virtual"` while a screen reader runs.

## Animation

The panel's state holds its size, `panelHeight` and `panelWidth`, in place of the web's `--collapsible-panel-*` variables. The panel lays its children out in a view of its own and measures that view, so the size is the content's whatever height the panel's style gives it. Animate the panel's height to `panelHeight` with `overflow: "hidden"`, and keep padding inside the content rather than on the panel.

The panel leaves through `onExit`. When it closes, it calls `onExit` with a `done` function and stays on screen until you call it, or until two seconds pass. Meanwhile it takes no touches and screen readers skip it. Without `onExit`, it unmounts at once, or hides with `keepMounted`.

`Grow` is the example's own: an effect that animates the height to the size it's given.

While it leaves, `panelHeight` is the height the panel had when it began closing, so a closing that interrupts an opening animates back from where it was, not from the content's full height. Once closed it is `0`. The state also has `startingStyle`, true for the panel's first frame after it appears, and `endingStyle`, true while it leaves.

```tsx
const [height] = useState(() => new Animated.Value(0))

<CollapsiblePanel
  render={<Animated.View style={{ height, overflow: "hidden" }} />}
  onExit={(done) =>
    Animated.timing(height, {
      toValue: 0,
      duration: 200,
      useNativeDriver: false,
    }).start(() => done())
  }
>
  {(state) => <Grow height={height} to={state.panelHeight} />}
</CollapsiblePanel>
```

Opening settles at once, so `onOpenChangeComplete(true)` runs as the panel appears, before an opening animation ends. `onOpenChangeComplete(false)` runs once `done` is called, or at once without `onExit`. A panel open from the start reports neither.

## Accessibility

The collapsible follows the [WAI-ARIA disclosure pattern](https://www.w3.org/WAI/ARIA/apg/patterns/disclosure/), translated to React Native's accessibility props: the trigger has the button role and its expanded and disabled state. TalkBack says whether it's expanded or collapsed. React Native 0.88 says nothing on iOS for a collapsed trigger, so VoiceOver reads only its name until the panel opens. A double-tap opens or closes the panel. The panel is a `View` with no role, and while closed or leaving, screen readers skip it.

### Keyboard

With a hardware keyboard, with iOS Full Keyboard Access or on Android:

| Key        | Does                                                         |
| ---------- | ------------------------------------------------------------ |
| Tab        | Moves to the next control, and Shift-Tab to the previous one |
| Arrow keys | Move between controls, on Android only                       |
| Space      | Opens or closes the panel from the trigger                   |
| Enter      | Opens or closes the panel, on Android only                   |

Native never reports where the screen reader's focus is, so closing a panel with focus inside it leaves focus to the OS rather than moving it back to the trigger.
