Use radios for a short list of choices where only one can be picked, like a shipping speed or a plan. The group keeps one value, and each radio is its own accessible element.

## Installation

```bash
npm install @ui-sdk/react-native @ui-sdk/core
```

## Composition

Use the following composition to build a `RadioGroup`:

```text
RadioGroup
├── Radio
│   └── RadioIndicator
└── Radio
    └── RadioIndicator
```

`Radio` renders a `Pressable`, and `RadioGroup` and `RadioIndicator` render a `View`.

## Usage

Import the parts and put them together. A native view has no `<label>` to wrap it in, so put the label's text inside the radio: it names the radio, and a tap anywhere on the row checks it.

```tsx
import { Radio, RadioGroup, RadioIndicator } from "@ui-sdk/react-native/radio"
import { Text, View } from "react-native"

function Example() {
  return (
    <RadioGroup aria-label="Shipping speed" defaultValue="standard">
      <Radio value="standard">
        <View style={styles.circle}>
          <RadioIndicator style={styles.dot} />
        </View>
        <Text>Standard</Text>
      </Radio>
      <Radio value="express">
        <View style={styles.circle}>
          <RadioIndicator style={styles.dot} />
        </View>
        <Text>Express</Text>
      </Radio>
    </RadioGroup>
  )
}

export { Example }
```

The indicator is mounted while its radio is checked. Draw it with views, not a text glyph: text inside the radio becomes part of its name.

Name the group with `aria-label`, and show the same words as a heading above it. A group's name may reach no screen reader yet, since React Native has no way to give a container one, so make each radio's own name clear without it.

## Controlled

## Forms

A native view takes part in no form, so the group has no `name` or `form` prop and renders no hidden input. Read the value from `onValueChange` or a controller, and reset it by setting it. `required` stays in the state for your styles and labels.

## Animation

The indicator leaves through `onExit`. When its radio unchecks, the indicator calls `onExit` with a `done` function and stays mounted until you call it, or until two seconds pass. Meanwhile it takes no touches and screen readers skip it. Without `onExit`, it unmounts at once.

```tsx
const scale = useRef(new Animated.Value(1)).current

<RadioIndicator
  onExit={(done) =>
    Animated.timing(scale, {
      toValue: 0,
      duration: 150,
      useNativeDriver: true,
    }).start(done)
  }
  render={<Animated.View style={{ transform: [{ scale }] }} />}
/>
```

The indicator's state also has `startingStyle`, true for its first frame after it appears, and `endingStyle`, true while it leaves. `keepMounted` keeps the indicator mounted while unchecked, so its style can follow `checked`.

## Styling

Style each part with a function of its state, like `(state) => [styles.circle, state.checked && styles.checked]`. Each part receives the fields listed under [Part State](#part-state). The radio gets a second argument, `{ pressed, hovered, focused }`, for press feedback, and keyboard focus on Android.

| Prop            | On               | Receives                                                          |
| --------------- | ---------------- | ----------------------------------------------------------------- |
| `onValueChange` | `RadioGroup`     | `(value, details)`: the checked value, and the [reason](#reasons) |

## Accessibility

Radio groups follow the [WAI-ARIA radio group pattern](https://www.w3.org/WAI/ARIA/apg/patterns/radio/), translated to React Native's accessibility props. Each radio has the `radio` role with its checked and disabled state, so VoiceOver and TalkBack announce it as a radio button, checked or unchecked, and a double-tap checks it. Each radio is its own accessible element, reached by swiping.

### Keyboard

With a hardware keyboard, with iOS Full Keyboard Access or on Android:

| Key        | Does                                                        |
| ---------- | ----------------------------------------------------------- |
| Tab        | Moves to the next radio, and Shift-Tab to the previous one  |
| Arrow keys | Move between radios, on Android only, without checking them |
| Space      | Checks the focused radio                                    |
| Enter      | Checks the focused radio, on Android only                   |

Every radio is its own stop: React Native delivers no arrow keys to views, so the group's single tab stop and its arrow keys, which check a radio as they move, aren't built.
