A hover card shows a preview of where a link goes, like a person's profile, to someone who rests a pointer on it. On a touch screen it stays closed, and a tap follows the link. With a pointer, like a trackpad on an iPad, it opens when the pointer rests on the link.

## Installation

```bash
npm install @ui-sdk/react-native @ui-sdk/core
```

The content renders in the [`OverlayHost`](../installation#wrap-your-app) that wraps your app. Without one, it renders in place and warns in development.

## Composition

Use the following composition to build a `HoverCard`:

```text
HoverCard
├── HoverCardTrigger
└── HoverCardContent
    └── HoverCardArrow
```

`HoverCardTrigger` renders a `Pressable` with the link role, and `HoverCardContent` and `HoverCardArrow` a `View`. A link on native has no `href`: follow it in the trigger's `onPress`, with your router or `Linking`. The content renders in the `OverlayHost`, so context from your own provider placed between `HoverCard` and `HoverCardContent` doesn't reach it: put it above your app's `OverlayHost` or inside the content. The library's own context does reach it.

The card only adds a preview for people with a pointer: everything in it should be reachable from the screen the link opens, since touch and screen reader users never open it. For a tip on a button, use a [Tooltip](./tooltip). For content that opens with a press, use a [Popover](./popover).

## Usage

Import the parts and put them together. Give the content a look, not a position:

```tsx
import {
  HoverCard,
  HoverCardContent,
  HoverCardTrigger,
} from "@ui-sdk/react-native/hover-card"
import { Linking, StyleSheet, Text } from "react-native"

function Example() {
  return (
    <HoverCard>
      <HoverCardTrigger
        onPress={() => Linking.openURL("https://example.com/people/hollis")}
      >
        <Text>@hollis</Text>
      </HoverCardTrigger>
      <HoverCardContent style={styles.card}>
        <Text>Hollis Grant</Text>
        <Text>Design engineer on the payments team.</Text>
      </HoverCardContent>
    </HoverCard>
  )
}

const styles = StyleSheet.create({
  card: { width: 260, padding: 12, borderRadius: 10, backgroundColor: "#fff" },
})

export { Example }
```

## Pointer

A card opens when a pointer, like a mouse or a trackpad, rests on its link for `delay`, 600 milliseconds by default, and closes once the pointer has left the link and the card for `closeDelay`, 300 milliseconds by default. The pointer can move from the link onto the card within `closeDelay` without closing it, so `closeDelay` is at least 100 ms on native, as Tooltip's is. React Native reports a pointer only once your app turns on its W3C pointer events: `RCTSetDispatchW3CPointerEvents(YES)` on iOS and `ReactFeatureFlags.dispatchPointerEvents = true` on Android, before React Native starts. In an Expo app, that's in the native project `expo prebuild` generates, or in a config plugin. Without them, and on a touch screen, a card never opens on hover. A finger's pointer events never open it.

`disabled` stops the card from opening and leaves a plain link.

## Touch

A tap on the link only presses it: the card stays closed and your `onPress` runs. A long press doesn't open it either. An open card, like one opened from code, closes on a press anywhere else, on Android's back and on VoiceOver's escape gesture.

## Side

`side` picks where the card opens: `"bottom"` by default. `align` lines it up with the start, center or end of the link. It flips to the other side when there isn't room, and shifts along the link to stay on screen. Its state's `side` says where it landed. `sideOffset` is the gap to the link, 4 points by default, `alignOffset` shifts it along the link, and `collisionPadding` keeps it from the edges of the space it may use. `anchor` places it against something other than its link: a view, like a ref's `current`, or a point in window coordinates.

## Controlled

Pass `open` and update it in `onOpenChange`. Every change carries a [reason](#reasons). Call `details.cancel()` to stop it.

## One Card for Many Links

A feed or a list can share one card. Connect the links and the card to one `createHoverCardController<Payload>()`. Each link passes a `payload`, like its person, and the content reads it from its state. `controller.open({ payload })` opens the card from code.

## Animation

The content leaves through `onExit`, as in [Dialog](./dialog#animation): it stays on screen until you call `done`, or two seconds pass. Its state's `transformOrigin` is the point facing the link. `onOpenChangeComplete` runs once the card has finished opening or closing.

## Custom Rendering

Every part takes `render`, an element or a function of the native props, the part's state and `{ pressed, hovered, focused }`. Spread the props on a `Pressable` so the link keeps its role and its press.

## Styling

Style each part with a function of its state, like `(state, interaction) => [styles.link, interaction.hovered && styles.underlined]`. Each part receives the fields listed under [Part State](#part-state).

## Accessibility

The trigger stays a plain link, named by its text. React Native has no role for the card, so it's a plain view whose text a screen reader can reach while it's open; the rest of the screen stays reachable. Opening or closing it never moves the screen reader, except back to the link after VoiceOver's escape gesture on the card. The arrow is hidden from screen readers.

### Keyboard

With a hardware keyboard, with iOS Full Keyboard Access or on Android:

| Key   | Does                                                                   |
| ----- | ---------------------------------------------------------------------- |
| Tab   | Moves through the controls; keyboard focus on the link doesn't open it |
| Space | Presses the link                                                       |
| Enter | Does the same, on Android only                                         |
