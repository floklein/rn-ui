Use an OTP Input for a short code sent by text or email, like a sign-in or verification code. Each character gets its own slot, a code the keyboard suggests fills them all at once, and tapping a slot selects it so the next character replaces it.

## Installation

```bash
npm install @ui-sdk/react-native @ui-sdk/core
```

## Composition

Use the following composition to build an `OTPInput`:

```text
OTPInput
└── OTPInputGroup
    ├── OTPInputSlot
    └── OTPInputSlot
```

`OTPInput` renders a `View` holding the code, with one `TextInput` under the slots. That field takes focus, holds the whole code and is what screen readers reach. `OTPInputGroup` lays out a run of slots. Each `OTPInputSlot` draws the character at its zero-based `index`, and a tap on it selects that character. Add `OTPInputSeparator` between groups when the code is easier to read in sections.

Name the code with a `FieldLabel` inside a [Field](/docs/react-native/components/field), whose label tap starts editing it, or with `aria-label`. Groups, slots and separators are only drawn: they're hidden from screen readers and aren't keyboard stops. The field asks for `one-time-code`, so iOS offers a code from Messages or Mail above the keyboard, and Android's autofill service can offer one from an SMS.

## Usage

Import the parts and put them together:

```tsx
import {
  OTPInput,
  OTPInputGroup,
  OTPInputSlot,
} from "@ui-sdk/react-native/otp-input"

function Example() {
  return (
    <OTPInput maxLength={4} aria-label="Verification code">
      <OTPInputGroup style={{ flexDirection: "row", gap: 8 }}>
        <OTPInputSlot index={0} />
        <OTPInputSlot index={1} />
        <OTPInputSlot index={2} />
        <OTPInputSlot index={3} />
      </OTPInputGroup>
    </OTPInput>
  )
}

export { Example }
```

Without children, a slot shows its character in a `Text`. Pass a function of the slot's state to draw it yourself, like a caret in the empty active slot.

## Refused Text and Pasted Codes

`TextInput` reports an edit after it shows it, so a character that doesn't fit the pattern appears for a moment and then goes back, with the selection where it was. A pasted or autofilled code is cleaned the way it is on the web: spaces and dashes go, full-width digits become plain ones, and a whole code replaces what was there. Text with anything else in it, like "Your code is 123456", is refused rather than half pasted.

## Disabled and Read Only

Set `disabled` to stop the code from being edited or selected. Screen readers announce the field as dimmed or disabled, and Android's Tab skips it.

`readOnly` keeps the code from changing. React Native has no read-only field that stays enabled, so screen readers announce it as dimmed or disabled too, and Android's Tab skips it. `required` stays in the state, for your styles and labels. It isn't announced.

## Controller

Create a `createOTPInputController()` and pass it as `controller` to read, fill, clear, or start editing the code from another control. Writes use the `imperative` reason and pass through the same filtering and change callbacks as typing.

```tsx
const [code] = useState(createOTPInputController)

<Pressable onPress={() => code.setValue("123456")}><Text>Fill</Text></Pressable>
<Pressable onPress={() => code.focus()}><Text>Focus</Text></Pressable>
<OTPInput controller={code} aria-label="Verification code">
  ...
</OTPInput>
```

## Forms and Keys

A native view takes part in no form, so there's no `name`, `form`, submission or reset: read the code from `onValueChange`, `onValueCommit` or the controller. `TextInput` reports no arrow keys, Home or End, so those don't move between slots, and there's no undo history of the component's own. A paste is reported as `input-change`, like typing.

## Styling

Style each part with a function of its state, like `(slot) => [styles.slot, slot.active && styles.active]`. Draw the caret yourself in a slot whose `hasFakeCaret` is true: the field's own text, caret and selection are hidden. Every part receives the fields listed under [Part State](#part-state).

## Accessibility

There's no WAI-ARIA pattern for a one-time code. Screen readers reach one text field with the whole code, named by a `FieldLabel` or an `aria-label`; the slots, groups and separators are hidden from them. VoiceOver and TalkBack read the code as they read any field, and their own editing gestures move through it.

### Keyboard

With a hardware keyboard, with iOS Full Keyboard Access or on Android:

| Key       | Does                                                                           |
| --------- | ------------------------------------------------------------------------------ |
| Tab       | Moves to the field, which starts editing it, and on past it                    |
| A digit   | Replaces the selected slot's character, or fills the empty slot after the code |
| Backspace | Deletes the selected character, or the last one                                |
