Use a dialog for a task the user finishes before going back to the screen, like editing a profile or sharing a link.

## Installation

```bash
npm install @ui-sdk/react-native @ui-sdk/core
```

## Composition

Use the following composition to build a `Dialog`:

```text
Dialog
├── DialogTrigger
├── DialogBackdrop
└── DialogContent
    ├── DialogTitle
    ├── DialogDescription
    └── DialogClose
```

`DialogTrigger`, `DialogBackdrop` and `DialogClose` render a `Pressable`, `DialogContent` a `View`, and `DialogTitle` and `DialogDescription` a `Text`. A modal dialog renders its backdrop and content in one React Native `Modal`, which `Dialog` renders, so the backdrop sits under the content and the rest of the screen is hidden from screen readers. Context from a provider placed between `Dialog` and `DialogContent` doesn't reach the content: put a provider above `Dialog` or inside the content.

## Usage

Import the parts and put them together. Style the backdrop to cover the screen, and place the content over it:

```tsx
import {
  Dialog,
  DialogBackdrop,
  DialogClose,
  DialogContent,
  DialogDescription,
  DialogTitle,
  DialogTrigger,
} from "@ui-sdk/react-native/dialog"
import { StyleSheet, Text } from "react-native"

function Example() {
  return (
    <Dialog>
      <DialogTrigger>
        <Text>Edit profile</Text>
      </DialogTrigger>
      <DialogBackdrop style={styles.backdrop} />
      <DialogContent style={styles.content}>
        <DialogTitle>Profile</DialogTitle>
        <DialogDescription>Change how others see you.</DialogDescription>
        <DialogClose>
          <Text>Done</Text>
        </DialogClose>
      </DialogContent>
    </Dialog>
  )
}

const styles = StyleSheet.create({
  backdrop: { position: "absolute", inset: 0, backgroundColor: "#00000066" },
  content: { margin: 24, marginVertical: "auto", backgroundColor: "#ffffff" },
})

export { Example }
```

## Closing

A press on a Close part closes the dialog with the `"close-press"` reason, and its `value` becomes the close's `returnValue`. The dialog also closes when:

- the backdrop is pressed, with `"outside-press"`, unless `closeOnOutsidePress` is `false`;
- Android's back button or gesture is used, with `"back"`, through the `Modal`'s `onRequestClose`;
- VoiceOver's escape gesture, a two-finger Z, is made on its content, with `"escape-key"`.

Set `dismissible={false}` to refuse those three, and ask in `onDismissAttempt`. A refused back still belongs to the dialog: it never reaches your navigation.

## Focus

When the dialog opens, it asks VoiceOver or TalkBack to move to its title, which names it. `initialFocus="content"` moves to the content instead, and `"none"` leaves the screen reader where it is. When the dialog closes, it asks to move back to the trigger that opened it, unless `finalFocus` is `"none"`. A request does nothing without a screen reader running, and focusing a text field starts editing it.

## Animation

The content leaves through `onExit`. When the dialog closes, the content calls `onExit` with a `done` function and stays on screen, with the backdrop and the `Modal`, until you call it, or until two seconds pass. Meanwhile it takes no touches and screen readers skip it. Without `onExit`, the dialog leaves at once. The content's state has `startingStyle`, true for its first frame, and `endingStyle`, true while it leaves.

```tsx
const [progress] = useState(() => new Animated.Value(0))

<DialogContent
  render={<Animated.View style={{ opacity: progress }} />}
  onExit={(done) =>
    Animated.timing(progress, {
      toValue: 0,
      duration: 300,
      useNativeDriver: true,
    }).start(() => done())
  }
>
```

Opening settles at once, so `onOpenChangeComplete(true)` runs as the dialog opens. `onOpenChangeComplete(false)` runs once `done` is called, or at once without `onExit`.

## Modal

`modal={false}` makes a dialog that sits beside the screen: it renders above your screens in the [`OverlayHost`](../installation#wrap-your-app) that wraps your app, not in a `Modal`, the screen stays usable, and the escape gesture closes it only from inside it. A press on the screen goes through to what you pressed; pass `closeOnOutsidePress` to have it close the dialog too. `modal="trap-focus"` doesn't exist on native: a `Modal` isolates the dialog for screen readers, and a keyboard trap would need native code.

## Nested Dialogs

A dialog opened inside another renders inside its `Modal`, so it shows above it: iOS never shows a second `Modal` beside one that's open. The same holds for a dialog opened from code while another is open. Android's back button closes the topmost dialog and returns focus to its trigger.

## Opening from Anywhere

Create a controller with `createDialogController<Payload, Result>()` and pass it as `controller`, to the dialog and to triggers outside it, like one per row. Its `open({ payload })` opens the dialog and resolves once it closes, with why and the `returnValue`. A trigger's `payload` reaches the content's state the same way.

## Accessibility

The dialog follows the [WAI-ARIA modal dialog pattern](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/), translated to React Native: the trigger is a button, the `Modal` hides the rest of the screen from VoiceOver and TalkBack, and the title has the header role and names the dialog. React Native has no dialog role, so screen readers announce the title, not "dialog". On iOS the content is also marked `accessibilityViewIsModal`.

### Keyboard

With a hardware keyboard, with iOS Full Keyboard Access or on Android:

| Key   | Does                                                           |
| ----- | -------------------------------------------------------------- |
| Tab   | Moves through the controls, inside the `Modal` while it's open |
| Space | Opens the dialog from the trigger, or presses a Close part     |
| Enter | Does the same, on Android only                                 |
