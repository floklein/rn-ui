# What styling libraries need from a headless native component

Research for [issue #9](https://github.com/floklein/rn-ui/issues/9), feeding the decision "How state reaches native styles" (#18). Researched on 2026-11-13.

The question: what must a part of `@ui-sdk/react-native` accept and pass through so that NativeWind, Uniwind, Unistyles, Tamagui and plain `StyleSheet` can each style it by state.

## How to read this

Every fact is tied to a version and a source. Two labels say how far a claim was checked:

- **Read**: read in the library's source or docs at the version named. Nothing here was run on a device or in a test runner.
- **Inferred**: a conclusion drawn from what was read. Treat it as a hypothesis for the prototype to test.

## The answer in short

No library reads state from a headless component in the same way, but all of them can be served by one small contract, because every one of them ends at the same place: a React Native host component that receives a `style` value, and for the Tailwind libraries a `className` string.

| Library       | Attaches through                                                                            | A third-party part must                                                          | Reads state on native from                                                       |
| ------------- | ------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------- | -------------------------------------------------------------------------------- |
| NativeWind v4 | `className`, by swapping the element type inside a wrapped JSX runtime                      | reach the host through JSX the app compiles, or be wrapped with `cssInterop`     | `dataSet`, any prop named in an attribute selector (`aria-checked`), `disabled`  |
| NativeWind v5 | `className`, by resolving `react-native` to wrapped components in Metro                     | import its hosts from `react-native`                                             | `dataSet`, `disabled`, camel-cased attribute names                               |
| Uniwind       | `className`, by resolving `react-native` to wrapped components in Metro                     | import its hosts from `react-native`                                             | `data-*` props, `disabled`, Pressable's `pressed` and `focused`                  |
| Unistyles     | `style` only, with a Babel plugin that remaps `react-native` imports to bind the host's ref | pass `style` through unflattened, and have its path listed in `autoProcessPaths` | nothing: variants and dynamic functions are called by the user                   |
| Tamagui       | `styled()` or its own components, producing `style`                                         | accept `style`, or take a Tamagui element through `render`                       | its own props: variants, `disabled`, and press, hover and focus it tracks itself |
| `StyleSheet`  | `style` only                                                                                | accept `style`                                                                   | nothing: `Pressable` passes `{ pressed }` to a `style` function                  |

Three findings matter most for the decision:

1. **A function of state is the only mechanism all five accept**, as long as the part resolves it before the host sees it. `className` and `style` functions of state, plus the `render` function, cover every library with no library-specific code.
2. **Declarative state selectors cannot be served by one prop.** NativeWind reads `dataSet`, Uniwind reads `data-*` props, Tamagui and Unistyles read neither. gluestack ships both props on every part for this reason.
3. **Styles must be merged as arrays, never spread or flattened.** ui-sdk's web `mergeStyles` spreads objects, which would break Unistyles and Reanimated styles on native.

## React Native itself

`Pressable` is the only core component whose `style` and `children` take a function, and the state is `{ pressed }` alone.

- **Read.** The type is `ViewStyleProp | ((state: PressableStateCallbackType) => ViewStyleProp)` and the state type holds only `pressed` ([Pressable.js L35-L40, L147-L148](https://github.com/facebook/react-native/blob/v0.88.1/packages/react-native/Libraries/Components/Pressable/Pressable.js#L35-L40)). The docs for 0.88 say the same ([Pressable](https://reactnative.dev/docs/pressable#style)).
- **Read.** The function is called at render: `style={typeof style === 'function' ? style({pressed}) : style}`, and `Pressable` tracks `pressed` only when `style` or `children` is a function ([L249, L363-L365](https://github.com/facebook/react-native/blob/v0.88.1/packages/react-native/Libraries/Components/Pressable/Pressable.js#L249)).
- **Read.** `Pressable` maps `aria-checked`, `aria-disabled`, `aria-expanded`, `aria-selected` and `aria-busy` into `accessibilityState`, and `disabled` into it too ([L206-L260](https://github.com/facebook/react-native/blob/v0.88.1/packages/react-native/Libraries/Components/Pressable/Pressable.js#L206-L260)). So a part already has reason to put `aria-*` and `disabled` on its host.
- **Read.** A function inside a style array is dropped silently: `flattenStyle` skips every entry that is not an object ([flattenStyle.js L26-L30](https://github.com/facebook/react-native/blob/v0.88.1/packages/react-native/Libraries/StyleSheet/flattenStyle.js#L26-L30)). `View` takes no function at all.
- **Read.** `View`'s props in core contain no `dataSet`; a search of `Libraries/Components/View` and `Libraries/StyleSheet` finds none. `dataSet` is a React Native Web prop that the Tailwind libraries reuse as a convention.

## NativeWind v4 (4.2.7)

**How it attaches.** At build time the Babel preset sets the JSX import source to `react-native-css-interop` and rewrites calls to React's `createElement` ([babel.js](https://github.com/nativewind/nativewind/blob/35e054a9f328b7dee995a8e7f54456c7cfe7911c/packages/react-native-css-interop/babel.js), **read**). At runtime that JSX function swaps the element type for a wrapped one if the type is registered: `type = interopComponents.get(type) ?? type` ([wrap-jsx.ts L28](https://github.com/nativewind/nativewind/blob/35e054a9f328b7dee995a8e7f54456c7cfe7911c/packages/react-native-css-interop/src/runtime/wrap-jsx.ts#L28), **read**). `View`, `Text`, `Pressable`, `Image`, `TextInput`, `ScrollView` and the touchables are registered by default ([components.ts L24-L52](https://github.com/nativewind/nativewind/blob/35e054a9f328b7dee995a8e7f54456c7cfe7911c/packages/react-native-css-interop/src/runtime/components.ts#L24-L52), **read**). Anything else is wrapped by hand with `cssInterop(Component, { className: "style" })`, which resolves the class names and passes the result as `style` ([api.ts L37-L63](https://github.com/nativewind/nativewind/blob/35e054a9f328b7dee995a8e7f54456c7cfe7911c/packages/react-native-css-interop/src/runtime/native/api.ts#L37-L63), **read**).

**What the part must do.** The swap happens where the element is created, so the code that creates the host element has to go through the wrapped JSX runtime.

- **Read.** rn-primitives publishes its JSX uncompiled for this: every package builds with `options.jsx = 'preserve'` ([tsup.config.ts L14](https://github.com/roninoss/rn-primitives/blob/1bebe66b12e7ddd3c313226e0bc2ee02b6e78ab4/packages/checkbox/tsup.config.ts#L14)), so the app's Babel compiles it with NativeWind's import source.
- **Read, and the filter was run.** The `createElement` rewrite skips files whose path has a segment named `react`, `react-native`, `react-native-web` or `react-native-css-interop` ([babel-plugin.ts L20-L21](https://github.com/nativewind/nativewind/blob/35e054a9f328b7dee995a8e7f54456c7cfe7911c/packages/react-native-css-interop/src/babel-plugin.ts#L20-L21)). Running that regular expression on `node_modules/@ui-sdk/react-native/dist/index.js` returns `false`: a package whose folder is named `react-native` is excluded. `renderElement` in `@ui-sdk/react` calls `React.createElement` directly, so the same code published as `@ui-sdk/react-native` would not be intercepted.
- **Inferred.** A build that ships calls to `jsx` from `react/jsx-runtime` is not intercepted either, since the plugin rewrites only `createElement`.

**State variants.**

- **Read.** `[data-x]` selectors read `props.dataSet.x`, with the name camel-cased; other attribute selectors read the prop of that name, so `aria-checked:` reads `props["aria-checked"]` ([conditions.ts L415-L442](https://github.com/nativewind/nativewind/blob/35e054a9f328b7dee995a8e7f54456c7cfe7911c/packages/react-native-css-interop/src/runtime/native/conditions.ts#L415-L442), [normalize-selectors.ts L227-L238](https://github.com/nativewind/nativewind/blob/35e054a9f328b7dee995a8e7f54456c7cfe7911c/packages/react-native-css-interop/src/css-to-rn/normalize-selectors.ts#L227-L238)).
- **Read.** `:disabled` reads `props.disabled` ([normalize-selectors.ts L376-L383](https://github.com/nativewind/nativewind/blob/35e054a9f328b7dee995a8e7f54456c7cfe7911c/packages/react-native-css-interop/src/css-to-rn/normalize-selectors.ts#L376-L383)).
- **Read.** `:active`, `:hover` and `:focus` are tracked by the wrapper, which injects `onPressIn`, `onPressOut`, `onHoverIn`, `onHoverOut`, `onFocus` and `onBlur` and calls the original handlers first ([native-interop.ts L201-L241](https://github.com/nativewind/nativewind/blob/35e054a9f328b7dee995a8e7f54456c7cfe7911c/packages/react-native-css-interop/src/runtime/native/native-interop.ts#L201-L241)). A `View` that gains one of these is rendered as a `Pressable` ([render-component.tsx L55-L67](https://github.com/nativewind/nativewind/blob/35e054a9f328b7dee995a8e7f54456c7cfe7911c/packages/react-native-css-interop/src/runtime/native/render-component.tsx#L55-L67)).
- **Read.** Parent state exists as `group`: a parent with a `group` class shares its interaction state and attributes with descendants through context ([normalize-selectors.ts L280-L292](https://github.com/nativewind/nativewind/blob/35e054a9f328b7dee995a8e7f54456c7cfe7911c/packages/react-native-css-interop/src/css-to-rn/normalize-selectors.ts#L280-L292)). The parent has to be a wrapped component that received `className`.

**A `style` function.** **Inferred**: it does not compose. The wrapper treats the target `style` as inline rules and writes an object back ([native-interop.ts L411-L420, L1072-L1097](https://github.com/nativewind/nativewind/blob/35e054a9f328b7dee995a8e7f54456c7cfe7911c/packages/react-native-css-interop/src/runtime/native/native-interop.ts#L1072-L1097)); nothing in that path calls a function. `className` must be a string: the wrapper calls `state.className.split` ([L398](https://github.com/nativewind/nativewind/blob/35e054a9f328b7dee995a8e7f54456c7cfe7911c/packages/react-native-css-interop/src/runtime/native/native-interop.ts#L398)).

**Animation.** **Read.** A class with a transition or animation makes the wrapper render `Animated.createAnimatedComponent(Component)` from Reanimated in place of the component ([render-component.tsx L69-L84, L203-L235](https://github.com/nativewind/nativewind/blob/35e054a9f328b7dee995a8e7f54456c7cfe7911c/packages/react-native-css-interop/src/runtime/native/render-component.tsx#L69-L84)). The preset adds the Reanimated Babel plugin.

**With a `render` swap.** **Read.** Gaining a pseudo-class, an animation, a CSS variable or a container after the first render remounts the host; the source warns "Components need to be animated during the initial render otherwise they will remount" ([render-component.tsx L57-L115](https://github.com/nativewind/nativewind/blob/35e054a9f328b7dee995a8e7f54456c7cfe7911c/packages/react-native-css-interop/src/runtime/native/render-component.tsx#L57-L115)). **Inferred**: a class name computed from state can trigger this, so a part has to survive its ref detaching and reattaching. An element passed as `render` from app code already carries the wrapped type, so `cloneElement` keeps it.

## NativeWind v5 (5.0.0-rc.1, on `react-native-css` 3.0.7)

**How it attaches.** There is no JSX runtime any more. `withNativewind` turns on `globalClassNamePolyfill` ([metro.tsx L10-L14](https://github.com/nativewind/nativewind/blob/5.0.0-rc.1/src/metro.tsx#L10-L14), **read**), and with it the Metro resolver sends every import of `react-native` to `react-native-css/components`, for app code and `node_modules` alike ([resolver.ts L20-L60](https://github.com/nativewind/react-native-css/blob/3.0.7/src/metro/resolver.ts#L20-L60), [index.ts L66-L69](https://github.com/nativewind/react-native-css/blob/3.0.7/src/metro/index.ts#L66-L69), **read**). Each wrapped component maps `className` to `style` through `useCssElement` ([Pressable.tsx](https://github.com/nativewind/react-native-css/blob/3.0.7/src/components/Pressable.tsx), **read**).

**What the part must do.** Import its hosts from `react-native`, and forward `className` to them. A compiled build works.

**State variants.** **Read.** `[data-x]` reads `props.dataSet.x`, as in v4. Other attribute names are camel-cased before the lookup, so `aria-checked:` reads `props.ariaChecked`, not `props["aria-checked"]` ([selectors.ts L281-L287](https://github.com/nativewind/react-native-css/blob/3.0.7/src/compiler/selectors.ts#L281-L287), [attributes.ts L20-L27](https://github.com/nativewind/react-native-css/blob/3.0.7/src/native/conditions/attributes.ts#L20-L27)); 3.1.0-rc.1 is the same. `:disabled` reads `props.disabled`, and any pseudo-class other than hover, active, focus, disabled and empty drops the rule ([selectors.ts L236-L256](https://github.com/nativewind/react-native-css/blob/3.0.7/src/compiler/selectors.ts#L236-L256)).

**A `style` function.** **Read.** It does not compose with `className`. When both are present the merge produces `[classStyle, userStyle]` ([styles/index.ts L341-L370](https://github.com/nativewind/react-native-css/blob/3.0.7/src/native/styles/index.ts#L341-L370)), and React Native drops a function inside an array.

**Animation.** **Read.** As v4: the host is replaced by Reanimated's `createAnimatedComponent(type)` ([useNativeCss.ts L142-L148](https://github.com/nativewind/react-native-css/blob/3.0.7/src/native/react/useNativeCss.ts#L142-L148), [reanimated.ts](https://github.com/nativewind/react-native-css/blob/3.0.7/src/native/reanimated.ts)).

## Uniwind (1.13.2)

**How it attaches.** **Read.** The Metro resolver swaps `react-native` for Uniwind's own components for every importer: "On native, `react-native` resolves to `src/components/index.ts`" ([CONTEXT.md L128-L131](https://github.com/uni-stack/uniwind/blob/346d4e01dcf82211f76d19fa67d6d05169cbb8cd/CONTEXT.md#L128-L131)). Each wrapper resolves `className` and renders the real component with `style={[generated, props.style]}` ([View.tsx](https://github.com/uni-stack/uniwind/blob/346d4e01dcf82211f76d19fa67d6d05169cbb8cd/packages/uniwind/src/components/native/View.tsx)). `withUniwind` is for components that are not React Native's, and Uniwind's own guidance forbids wrapping React Native or Reanimated components with it ([SKILL.md L36](https://github.com/uni-stack/uniwind/blob/346d4e01dcf82211f76d19fa67d6d05169cbb8cd/skills/uniwind/SKILL.md?plain=1#L36)).

**What the part must do.** Import its hosts from `react-native` and forward `className`. A compiled build works.

**State variants.** **Read.** Data attribute variants match `data-*` props on the component, boolean or exact value ([CONTEXT.md L157](https://github.com/uni-stack/uniwind/blob/346d4e01dcf82211f76d19fa67d6d05169cbb8cd/CONTEXT.md#L157), [matches.test.ts L212](https://github.com/uni-stack/uniwind/blob/346d4e01dcf82211f76d19fa67d6d05169cbb8cd/packages/uniwind/tests/native/styles-parsing/matches.test.ts#L212)), not `dataSet`. `disabled:` reads `props.disabled`; `active:` and `focus:` come from `Pressable`'s own `pressed` and `focused`. A rule with a selector it cannot observe, "e.g. `[aria-disabled="true"]`", is skipped ([CONTEXT.md L156](https://github.com/uni-stack/uniwind/blob/346d4e01dcf82211f76d19fa67d6d05169cbb8cd/CONTEXT.md#L156)), so `aria-*` variants do nothing on native. Group variants are in the paid Uniwind Pro only ([pro.md L22](https://github.com/uni-stack/uniwind/blob/346d4e01dcf82211f76d19fa67d6d05169cbb8cd/skills/uniwind/references/pro.md?plain=1#L22)).

**A `style` function.** **Read.** It composes on `Pressable`, the only library where it does: `[classStyles, typeof props.style === 'function' ? props.style(state) : props.style]` ([Pressable.tsx L26-L41](https://github.com/uni-stack/uniwind/blob/346d4e01dcf82211f76d19fa67d6d05169cbb8cd/packages/uniwind/src/components/native/Pressable.tsx#L26-L41)).

**Animation.** **Read.** The open-source package has no class-driven animation. Uniwind Pro adds `animate-*` and `transition-*` on Reanimated 4 and swaps components for animated ones when it sees those classes ([pro.md L19, L98](https://github.com/uni-stack/uniwind/blob/346d4e01dcf82211f76d19fa67d6d05169cbb8cd/skills/uniwind/references/pro.md?plain=1#L19)). Pro is closed source, so this rests on its shipped guide alone.

## Unistyles (3.8.1)

**How it attaches.** **Read.** Through `style` only; there is no `className`. Styles from `StyleSheet.create` carry a hidden `unistyles_*` key that links them to C++ state. The Babel plugin replaces `react-native` imports with component factories that borrow the host's `ref` to register its shadow node, so theme and breakpoint changes update the view without a render ([Babel plugin, "Component factory"](https://github.com/jpudysz/react-native-unistyles/blob/bfc38160b938294cebc77e850ee3105ba9de29f8/apps/docs/src/content/docs/v3/other/babel-plugin.mdx)).

**What the part must do.**

- **Read.** Reach a React Native host imported from `react-native`. Files in `node_modules` are ignored unless listed in `autoProcessPaths`, and the docs tell library authors to have users add that option ([For library authors](https://github.com/jpudysz/react-native-unistyles/blob/bfc38160b938294cebc77e850ee3105ba9de29f8/apps/docs/src/content/docs/v3/other/for-library-authors.mdx)). Without it styles still apply but do not update on their own; the fallbacks are `withUnistyles(Component)`, which re-renders, then `useUnistyles` ([3rd party views](https://github.com/jpudysz/react-native-unistyles/blob/bfc38160b938294cebc77e850ee3105ba9de29f8/apps/docs/src/content/docs/v3/references/3rd-party-views.mdx)).
- **Read.** Merge styles with arrays. "Use the `[]` syntax to merge styles. Avoid spreading Unistyles." Spreading loses the C++ link and the merge order, and warns in development ([Merging styles](https://github.com/jpudysz/react-native-unistyles/blob/bfc38160b938294cebc77e850ee3105ba9de29f8/apps/docs/src/content/docs/v3/guides/merging-styles.mdx)).
- **Read.** Forward `ref` to the host: the factory needs it, and `Modal` and `TouchableWithoutFeedback` are unsupported because they expose none.

**State variants.** **Read.** None are read from the component. The user calls `styles.useVariants({ ... })` at the top of their own component, or a dynamic function such as `styles.item(checked)` ([variants](https://github.com/jpudysz/react-native-unistyles/blob/bfc38160b938294cebc77e850ee3105ba9de29f8/apps/docs/src/content/docs/v3/references/variants.mdx), [dynamic functions](https://github.com/jpudysz/react-native-unistyles/blob/bfc38160b938294cebc77e850ee3105ba9de29f8/apps/docs/src/content/docs/v3/references/dynamic-functions.mdx)). So state has to reach the user's code as a value.

**A `style` function.** **Read.** Unistyles' own `Pressable` accepts one and calls it with `{ pressed }` ([Pressable.native.tsx L53-L85](https://github.com/jpudysz/react-native-unistyles/blob/bfc38160b938294cebc77e850ee3105ba9de29f8/packages/unistyles/src/components/native/Pressable.native.tsx#L53-L85)). **Inferred**: a part's `style` function that returns `styles.item(state.checked)` works if the part hands the result on untouched.

**Animation.** **Read.** It defers to Reanimated: `Animated.View` with `useAnimatedStyle`, plus `useAnimatedTheme` and `useAnimatedVariantColor`. Styles are no longer flattened by Reanimated from 3.17.2 or 4.0.0-beta.3 ([Reanimated guide](https://github.com/jpudysz/react-native-unistyles/blob/bfc38160b938294cebc77e850ee3105ba9de29f8/apps/docs/src/content/docs/v3/guides/reanimated.mdx), [Merging styles](https://github.com/jpudysz/react-native-unistyles/blob/bfc38160b938294cebc77e850ee3105ba9de29f8/apps/docs/src/content/docs/v3/guides/merging-styles.mdx)).

## Tamagui (3.3.3)

**How it attaches.** **Read.** Through `styled(Component, { ... })` or its own `View` and `Text`. "The `styled()` function supports Tamagui views, React Native views, and any other React component that accepts a `style` prop" ([styled.mdx L91](https://github.com/tamagui/tamagui/blob/v3.3.3/code/tamagui.dev/data/docs/core/styled.mdx?plain=1#L91)). On native, every component Tamagui does not know is assumed to be a React Native view ([setupReactNative.ts L16-L17](https://github.com/tamagui/tamagui/blob/v3.3.3/code/core/web/src/setupReactNative.ts#L16-L17)).

**What the part must do.** Accept `style`. But there is a hard limit:

- **Read.** "React Native utility views like Pressable and TouchableOpacity are not supported targets for `styled()`. Their event handling logic conflicts with Tamagui" ([styled.mdx L87](https://github.com/tamagui/tamagui/blob/v3.3.3/code/tamagui.dev/data/docs/core/styled.mdx?plain=1#L87)). **Inferred**: a part that renders `Pressable` is the same case, so `styled(Part)` is safe for static styles and unsafe for Tamagui's press states.

**State variants.** **Read.** Variants are props of the styled component ([variants.mdx](https://github.com/tamagui/tamagui/blob/v3.3.3/code/tamagui.dev/data/docs/core/variants.mdx)). State modifiers are `hover:`, `press:`, `focus:`, `focus-visible:`, `focus-within:` and `disabled:`, the last "while `disabled={true}`", and parent state is `group-hover:`, `group-press:` and `group-focus:` under a parent marked `group` ([styles.mdx L165-L260](https://github.com/tamagui/tamagui/blob/v3.3.3/code/tamagui.dev/data/docs/intro/styles.mdx?plain=1#L165-L260)). In Tamagui's Tailwind mode, `data-*` and `aria-*` selectors are web-only and dropped on native ([tailwind.mdx L250-L260](https://github.com/tamagui/tamagui/blob/v3.3.3/code/tamagui.dev/data/docs/core/tailwind.mdx?plain=1#L250-L260)).

**Element swapping.** **Read.** Tamagui 3 has a `render` prop with the same shape as ui-sdk's: a string, an element whose props merge, or `(props, state) => element` with `state.hover`, `state.press`, `state.focus` and `state.disabled` ([styled.mdx L104-L172](https://github.com/tamagui/tamagui/blob/v3.3.3/code/tamagui.dev/data/docs/core/styled.mdx?plain=1#L104-L172)). **Inferred**: the natural way to use Tamagui with a ui-sdk part is the reverse of `styled(Part)`: pass a Tamagui element to the part's `render`, in the function form so state becomes variant props, `render={(props, state) => <Box {...props} checked={state.checked} />}`. Tamagui's components take `onPress`, `onPressIn`, `onPressOut` and `onLongPress` as props ([types.tsx L406-L409](https://github.com/tamagui/tamagui/blob/v3.3.3/code/core/web/src/types.tsx#L406-L409)), so a part's behavior can ride on them.

**Animation.** **Read.** An animation driver that needs its own component, such as Reanimated's, replaces the rendered element with the driver's `View` or `Text` ([createComponent.tsx L636-L643](https://github.com/tamagui/tamagui/blob/v3.3.3/code/core/web/src/createComponent.tsx#L636-L643), [createAnimations.tsx L1020-L1021](https://github.com/tamagui/tamagui/blob/v3.3.3/code/core/animations-reanimated/src/createAnimations.tsx#L1020-L1021)). **Inferred**: `styled(Part)` with a transition would render `Animated.View` in the part's place and lose its behavior, which is one more reason to go through `render`.

## What works in practice

- **rn-primitives 1.5.2.** **Read.** Parts spread the rest of their props, `className` and `style` included, onto a `Pressable` or `View` from `react-native`, and put `aria-checked`, `aria-disabled`, `role`, `accessibilityState` and `disabled` on it ([checkbox.tsx L55-L70](https://github.com/roninoss/rn-primitives/blob/1bebe66b12e7ddd3c313226e0bc2ee02b6e78ab4/packages/checkbox/src/checkbox.tsx#L55-L70)). They emit no `dataSet` or `data-*` on native. Element swapping is `asChild` with a `Slot` that clones the child, joins `className` strings, composes handlers and merges `style` into arrays while keeping a function a function ([slot.tsx L223-L275](https://github.com/roninoss/rn-primitives/blob/1bebe66b12e7ddd3c313226e0bc2ee02b6e78ab4/packages/slot/src/slot.tsx#L223-L275)).
- **React Native Reusables.** **Read.** The NativeWind and Uniwind registries hold the same component code. State styling is done in JavaScript, not with selectors: `props.checked && cn('border-primary', checkedClassName)` and `props.disabled && 'opacity-50'` ([checkbox.tsx L28-L29](https://github.com/founded-labs/react-native-reusables/blob/da1e1f222aaf8dcd6c55aaa6307a28831c1697f4/packages/registry/src/nativewind/components/ui/checkbox.tsx#L28-L29)), and state the consumer does not hold is read from a context hook, `AccordionPrimitive.useItemContext()` ([accordion.tsx L67](https://github.com/founded-labs/react-native-reusables/blob/da1e1f222aaf8dcd6c55aaa6307a28831c1697f4/packages/registry/src/nativewind/components/ui/accordion.tsx#L67)). `aria-invalid:` and `focus-visible:` classes sit under `Platform.select({ web })`. Text inside a button gets its classes through a `TextClassContext`, since native text does not inherit ([button.tsx L95](https://github.com/founded-labs/react-native-reusables/blob/da1e1f222aaf8dcd6c55aaa6307a28831c1697f4/packages/registry/src/nativewind/components/ui/button.tsx#L95)).
- **gluestack-ui core 5.0.15.** **Read.** It does use selectors, `data-[checked=true]:bg-primary`, and to make them match under both Tailwind libraries every part emits the state twice, with the comments "data attributes for uniwind" above `data-checked={...}` props and "data attributes for nativewind" above a `dataSet={{ checked: ... }}` prop ([CheckboxIndicator.tsx L20-L52](https://github.com/gluestack/gluestack-ui/blob/b712c8541c85d57becbd1a1b2ba150a369223eb6/packages/gluestack-core/src/checkbox/creator/CheckboxIndicator.tsx#L20-L52)). The values are the strings `'true'` and `'false'`.

## The minimal contract

A native part works with all five if it does the following. Each line names the library that forces it.

1. **Render a host imported from the `react-native` root** (`View`, `Text`, `Pressable`, `TextInput`, `ScrollView`), as the part's own outermost element. NativeWind v5 and Uniwind attach by resolving that import; Unistyles' Babel plugin remaps it.
2. **Accept `className` and forward it as a string, without reading it.** NativeWind and Uniwind need it on the host; the others ignore it. If it may be a function of state, the part resolves it first: the libraries expect a string, and NativeWind v4 calls `split` on it.
3. **Accept `style` as React Native's `StyleProp`, and as a function of the part's state.** The part calls the function; the host never receives one. NativeWind v4 and v5 drop a function that arrives with `className`.
4. **Merge styles as arrays, `[partStyle, userStyle]`.** Never spread, never `StyleSheet.flatten`. Unistyles' styles and Reanimated's animated styles are not plain objects. This is the one place the web `mergeProps` cannot be reused as it is.
5. **Forward `ref` to the host and survive it reattaching.** Unistyles and Reanimated bind to the host through it, and NativeWind remounts the host when a class adds an animation or a pseudo-class.
6. **Pass unknown props through to the host**, so `dataSet`, `data-*` and `cssInterop={false}` set by the user or by a wrapper arrive.
7. **Put `disabled` and `aria-*` on the host as real props.** `disabled:` reads `props.disabled` in NativeWind, Uniwind and Tamagui, and `Pressable` builds `accessibilityState` from them.
8. **Compose event handlers, later first, when merging a `render` element's props.** NativeWind injects `onPressIn`, `onPressOut`, `onFocus`, `onBlur`, `onHoverIn` and `onLayout` and calls the ones it was given. The web `mergeProps` already does this.
9. **Offer `render` as an element or `(props, state) => element`, and `children` as a function of state.** It is the only route for Tamagui variants and Unistyles variants, both of which need state as a value in the user's code, and for swapping in `Animated.View`.
10. **Carry everything a style needs in the part's state**, including `pressed` and the state of its ancestors (an indicator's `checked`, an item's `highlighted`). **Inferred**: the part should track `pressed` itself from `onPressIn` and `onPressOut`, since passing `Pressable` a `style` function to learn it would break rule 3. Parent-to-child state has no shared mechanism: NativeWind and Tamagui have `group`, Uniwind has it only in Pro, Unistyles and `StyleSheet` have nothing.

With this contract the same component code styles a part in every library through functions of state:

```tsx
<Checkbox.Root className={(s) => cn("size-4 border", s.checked && "bg-primary")} />
<Checkbox.Root style={(s) => [styles.box, s.checked && styles.checked]} />
<Checkbox.Root style={(s) => styles.box(s.checked)} />
<Checkbox.Root render={(props, s) => <Box {...props} checked={s.checked} />} />
```

## Where no single contract works

1. **Declarative state selectors.** `data-[checked]:` needs `dataSet={{ checked }}` for NativeWind and a `data-checked` prop for Uniwind, and `aria-checked:` matches a prop in NativeWind v4, a camel-cased name in v5 and nothing in Uniwind. A part can emit both `dataSet` and `data-*`, as gluestack does, but that is a contract with two libraries' internals, and it still leaves Tamagui and Unistyles on functions. The values differ too: gluestack writes `'true'` and `'false'`, where web's presence attributes are `""` or absent, so `data-[checked]:` and `data-[checked=true]:` cannot both be right across hosts.
2. **Wrapper-style attachment and functions of state.** `cssInterop(Part)`, `withUniwind(Part)`, `withUnistyles(Part)` and `styled(Part)` sit outside the part and consume `className` or produce `style` before the part runs. A `className` function passed to a wrapped part reaches the wrapper, which expects a string. Functions of state work only when the part is outermost and the library attaches at the host, which is what rules 1 and 2 arrange.
3. **How the published build is compiled.** NativeWind v4 needs the JSX that creates hosts left uncompiled, as rn-primitives ships it, or a per-part `cssInterop` call by the user. NativeWind v5 and Uniwind need nothing. Unistyles needs the package path in the user's `autoProcessPaths`. These do not conflict, but v4 dictates the build format, and its file filter excludes a package folder named `react-native`.
4. **Tamagui and `Pressable`.** `styled()` does not support `Pressable`, and a Tamagui animation replaces the element. A part that needs Tamagui's press states or transitions has to hand its behavior to a Tamagui element through `render`, so behavior must be expressible as props (`onPress`, `onPressIn`, `onPressOut`, `disabled`, `aria-*`, `role`, `ref`) and not depend on the host being a `Pressable`.
5. **Animation, and exit animation above all.** Each library animates by owning the host: NativeWind and Uniwind Pro swap it for a Reanimated component when a class asks, Tamagui swaps it for its driver's `View`, Unistyles and `StyleSheet` leave it to the user's `Animated.View`. None reports that a transition has ended in a common way, so there is no native counterpart to waiting for `animationend`. **Inferred**: presence on native needs an explicit signal from the user's code, which belongs to the Motion decision, not this one.
6. **CSS variables.** `--anchor-width` and `--available-height` have no carrier. NativeWind has `vars()` and Uniwind has `ScopedVariables`, each private to its library. **Inferred**: geometry has to arrive as numbers in state or in the part's own `style`.
7. **Text.** Native text does not inherit color or font from a parent view, so a class on a button does not reach its label. Reusables works around it with a context of its own. This is the styling library's or the design system's job, but it means each text part needs its own `className` and `style`.
